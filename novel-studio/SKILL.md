# 小说创作工作室

以具备文学奖竞争力的长篇作品为打磨方向；不承诺获奖，不用自评分代替阅读证据。不用于一般文案润色。

## 分工与执行边界

主 agent 负责沟通、规划、派工、只读检查和验收。正文、试写、改写和场景计划由真实创作子 agent 编写；大纲、设定、摘要、索引、历史、任务账本和交接等作品文件由相应子 agent 维护。当前稿必须由未参与其写作的另一真实子 agent 评审。不得模拟角色、自评或以机械修复为由由主 agent 代写作品文件。

宿主须提供真实派工、传递资料和取回结果的能力；支持顺序派工即可。缺此能力时保留现场并说明迁移条件，不代写代评，不自行改宿主配置。文件里的身份与授权只是申报，主 agent 对照实际宿主记录、作者原话和版本核验。已结束的子任务不能续聊时新派真实 agent，传递产物与哈希，如实记录身份和阅读历史。

## 每次执行的最小入口

1. 确认作品绝对路径，读顶层 `索引.md`、`创作约定/写作进度与接续说明.md`、`创作约定/作品状态.json` 和当前任务账本入口；先处理 `pending_operations`、失效证据和手改，不覆盖已有作品。
2. 恢复作者方向、语言标准、授权和当前阶段；未选合作方式先试写，不把沉默当批准。派工前用 `taskctl.py gate --book BOOK --stage ID --before KIND` 检查前置验收；只问阻塞执行且文件中没有答案的问题。
3. 按下表读取本次所需小节，提供精确文件、章节、写入范围与验收条件给子 agent。无需每章通读所有参考文档，也不把含未来秘密的整份资料交给首读者。
4. 准备 → 草稿 → 独立首读及资料核查 → 必要修订与当前稿复核 → 正式采用及资料同步 → 主 agent 验收。每一步保留真实产物、输入版本和未完项；缺评审或同步未完不得称为正式章完成。详细依赖和四组派工示例见协作流程。

## 完成与接续

作品顶层按连续章号保存当前正式正文，资料在有索引的子目录；工具生成的历史快照和采用日志只读保留。重要事实区分正文、作者要求、计划、推测和角色误信，带对象标识、故事时点、出处及核对版本。摘要用于定位，不代替原文。逐章筛查所有资料类别，只详细更新实际变化或构成约束的内容。

首读先只给正文、必要前文与中性背景，保存原始反馈后才补意图和秘密；无法隔离时注明普通评审及限制。修订复核如实标记阅读历史，不能冒充新读者盲读。开书或重大风格调整按文学指南做同场景对照试写。

子 agent 提交 `submitted` 后由主 agent 核验文件、哈希、评审与授权，再派资料子 agent 记录验收为 `done`；版本变化按影响重新打开任务。采用用 `chapterctl adopt`，资料与索引同步后用 `finish`；阶段关闭用 `taskctl close` 并留下下一阶段或本轮终点。全书定稿另须完整当前稿的整体阅读、修订及复核证据和 `bookctl check`；章节完成不替代全书定稿，工作稿可按既有授权导出。

已授权普通任务继续；越出重大方向、缺真实子 agent、冲突或现场不完整时保留证据并处理。两轮针对性返工仍受阻则向作者说明分歧与选择。换会话或工具依靠普通文件与真实来源接续，不依赖旧子任务存活。
