# 阶段任务与验收

每部作品使用 `创作约定/任务计划与验收.md` 保存阶段、任务、依赖、证据及验收状态。主 agent 制定计划、派工、统一写入行政任务记录并核验；子 agent 返回实际产物、哈希与未完项。纯验收、状态更新和回读不另派子 agent。任务文件是执行入口，正文、评审、采用及中断状态仍由原有文件承担，不能用勾选覆盖其检查结果。

## 单文件约定

同一 Markdown 文件包含可读的阶段/任务复选框及一个带标记的 JSON 数据区。JSON 是唯一任务数据，复选框由 `taskctl` 从它生成；不另存一份 JSON 账本。只改复选框不能形成有效完成记录，`check` 会发现显示与数据不一致。通过 `plan`、`update` 维护任务；确需手工补充数据时，先保留历史，再修改数据区并运行 `render`，不能删掉必做项来修复告警。权威 JSON 只位于 `<!-- taskctl:begin -->` 与 `<!-- taskctl:end -->` 受管标记内，区外可保留说明和其他 JSON 示例；`render` / `update` 保留区外内容。重复、缺失或乱序的受管标记须先核对，不能选取任意 JSON 代替权威数据。

每项包含稳定的阶段/任务标识、任务种类、负责角色、执行状态、前置任务、输入版本、验收条件、产物路径与哈希、真实验收依据及历史。阶段内任务 ID 如 `S02.prepare`，宿主实际任务 ID 另存于派工和产物记录中，换工具时不改变作品内 ID。新阶段默认 `workflow_version: 2`；旧阶段缺此字段按 v1 读取，账本外层仍为 `schema_version: 1`，不能混淆这两种版本。

状态为 `todo`（待执行）、`doing`（进行中）、`submitted`（已提交待验收）、`done`（已验收）、`blocked`（受阻）、`not_applicable`（不适用）。只有 `done` 显示已完成勾选。阶段另可由 `outline-rescope` 标为 `superseded`（按作者新选择或明确修改要求被替代的历史终止）；它不是任务状态，也不表示章目通过，原任务状态保持真实。子 agent 报完成先提交产物；主 agent 核实内容、版本、依赖、真实派工及授权后，直接记录 `verification.agent_id` 与可核对的 `verification.source`。身份和验收文字只是申报，脚本不认证其真实性。

任务维护是每次交付的一部分：先确认前置已验收并登记 `doing`，执行者写前自行核验 gate；产物一返回就登记 `submitted`、实际路径及哈希，主 agent 核验后再记 `done`，然后才能派依赖它的下一项。不得把整个写章流程打成一个先产出后补账的任务包，也不把 `submitted` 当作已完成；下文 `outline` 的候选待最终接受是唯一明示的审读依赖特例。中断或部分产出立即保留真实状态、已写文件和缺项，不能为保持勾选完整而补造过去的批准。

核心任务必须执行；如不需要改稿，`revise` 或 `structural_revision` 记录无需修改的依据，仍须由相应评审复核。额外条件任务可用 `not_applicable`，但须有原因及验收依据，不能用它跳过独立评审、作者授权或资料同步。阶段没有适用素材缺口时无需强行查资料，缺外部读者不构成停止创作的条件。

## 必做步骤与滚动计划

`plan` 根据工作流生成必做项和依赖，不能遗漏、重复、取消或解除其模板前置关系：

| 工作流 | 必做步骤，按依赖顺序 |
| --- | --- |
| `materials`：仅整理既有资料 | `scope` 本轮授权与输入／输出范围 → `organize` 整理及来源核对 → `next_plan` 接续或真实终点 |
| `review_only`：只读审稿 | `scope` 本轮授权与输入／输出范围 → `read_only_review` 独立阅读及审稿报告 → `next_plan` 接续或真实终点 |
| `planning`：方向与构思 | `direction` 方向与授权 → `concept` 构思验证 → `next_plan` 后续计划 |
| `outline`：全书章目（v2） | `outline_draft` 候选 → `outline_review` 独立审读 → 至多两轮 `outline_revision_N → outline_recheck_N` → `outline_acceptance` 当前候选最终接受 → `next_plan` 首卷接续 |
| `chapter`：写章或改章 | `prepare` 写前准备 → `draft` 草稿 → `first_read` 首轮阅读 → `review` 资料与连贯性核查 → `revise` 意见处理 → `recheck` 当前稿复核 → `adopt` 正式采用 → `sync` 资料同步 → `next_plan` 后续计划 |
| `trial`：试写后拟选声并采用 | 在 `chapter` 的 `prepare` 与 `draft` 之间增加 `voice_trial` 同场景候选对照；再按下文追加匿名阅读与作者选声节点，遵守已有视角及授权 |
| `trial_only`：仅交候选和比较反馈 | `prepare` 写前准备 → `voice_trial` 同场景候选 → `voice_first_read` 独立比较反馈 → `next_plan` 真实终点或新授权接续；不选声、不写采用章稿、不采用 |
| `finalization`：全书定稿 | `whole_read` 整体阅读 → `structural_revision` 结构意见处理 → `whole_recheck` 全稿复核 → `finalize` 定稿验收 → `next_plan` 后续安排 |

任务可合并承接一次实际派工的多个产物，执行记录分别引用证据，不要求每个任务新开一个 agent。任务依赖表示交付物已被验收，不能只凭派工已发出就进入下一步。`depends_on` 只引用同阶段任务；跨阶段通过关闭阶段、`next_stage` 和输入版本衔接，避免当前任务等待尚不可执行的未来阶段。额外条件或并行任务可增加到同一数据区，列清依赖；不得反向影响首读隔离。

### 全书章目：有限迭代与最终验收

方向与故事引擎已确认、作者要求先确认全书章目时，用 `plan` 建立 v2 `outline` 阶段，不再手工拼出审读与返修图；`planning` 只负责方向与构思，不因有 `concept` 就视为全书章目已接受。

旧项目已在 `planning` 手工加入章目任务时，先用正式回读工具核对历史、候选、报告、真实作者选择与未完职责，保留原 ID、kind、证据及状态；本工具不自动将已开工阶段转换为 `outline`。这类旧账本须受审迁移或沿真实现有职责恢复：不删除原任务、不把修订或报告完成伪记为章目通过，也不能直接执行未来新阶段。没有可验证映射时明确报告迁移缺项，不承诺可一键接续；新模板供合法新阶段使用。

```json
{"id":"S02","title":"全书章目确认","workflow":"outline"}
```

#### 最低通过线与意见分类

章目做到“足以开始已授权正文”，不要求先写出小说或穷尽未来细节。当前候选必须覆盖约定的卷／章范围，逐章可定位主要行动、必要条件、前后状态及承接；独立审读以四项硬标准核对：行动可执行（`actionable`）、关键时间与身份不互斥（`timeline`）、关键转折至收束因果不断链（`causal_chain`）、不违背作者硬边界（`author_boundaries`）。这些标准不要求真实金额与全部史实先确定，但资金缓冲、移动／权限／身份条件及必要退路必须在故事内部成立；不能把人物无法行动写成“史实待核”来放行。

| `category` | 判断与处置 |
| --- | --- |
| `blocker`：结构硬阻断 | 行动不可执行、关键时间／身份互斥、结局因果断链、违反作者硬边界；必须最小修正并复核，不得仅改标签或以作者泛授权豁免。 |
| `risk`：需跟踪风险 | 不承重的现实／史实待核、审美偏好及非关键配角细节；可以带入正文，`tracking` 须明确责任者、最迟处理章／场景和追踪位置。若后来成为当前行动条件，只暂停受影响范围补核，不自动退回全书规划。 |
| `blank`：可保留局部留白 | 不妨碍当前行动理解，且后续场景不依赖未定事实；说明为何可留、何时会转为需处理事项。不为填满模板返工。 |

每条意见必须带稳定 `id`、具体 `chapters`（正整章号列表）、`category`、`minimum_fix`（最小修正或保留条件）及 `verification`（可执行核对方法）；`risk` 另有 `tracking`。审读者不能在同一输入、同一影响和已解释处置未变时，因个人偏好换轮追加新的全书准入要求。真正新发现的硬阻断照实记录，但也受两轮出口约束。

#### 内置任务图与候选状态

初始图是 `outline_draft → outline_review → outline_acceptance → next_plan`。首轮审读要求修订时，主 agent 调用 `outline-revise`，脚本在最终接受之前插入唯一的 `outline_revision_1 → outline_recheck_1`；仍需修订时同命令再插入 `outline_revision_2 → outline_recheck_2`。每轮 candidate 另存新文件，旧稿、报告和哈希保持不可变；不覆盖 v1、不手改数组或 `depends_on`，也不复制同一 ID。候选、修订、审读及复核一经 `submitted`，其 `inputs/outputs/checks` 即冻结，只可同证据行政验收或回读，不能原地换稿、重开 `doing` 来规避轮数。各轮报告路径必须与所有候选及其他轮报告不同。

`outline_draft=submitted` 只表示候选已交付等待最终接受：内置审读允许在该状态下合法运行，游标跳过这项等待接受的候选，指向真实待执行的审读／修订／复核／接受。此特例不放宽普通章节依赖。每次返修自动重绑 `outline_acceptance` 到最新复核，并保持 `next_plan` 依赖最终接受，旧轮报告完成不能放行正文。章目版本通过新增的有限轮次推进，不用普通任务重开路径修改已提交候选；其他任务重开及变更仍按通用失效规则处理。

```bash
python "$SKILL/scripts/taskctl.py" outline-revise --book "$BOOK" --request /绝对路径/章目返修请求.json
```

```json
{"stage":"S02","reason":"当前独立审读指出的具体硬缺口及最小修订范围","verification":{"agent_id":"实际主agent标识","source":"真实报告及调度核验出处"}}
```

修订任务 `done` 验收的是本轮新稿与意见处置交付；复核报告 `done` 验收的是对当前版本的独立报告完整，即使其结论为 `revise` 也可完成报告任务。两者均不表示章目通过。`outline_acceptance=done` 才代表最终接受，须最新复核 `pass`、四项硬标准全为真、无 `blocker`，并有作者对当前候选的明确确认；脚本随后将原 `outline_draft` 封存为 `done`，其输出仍指向原始候选，当前接受的版本由最终验收绑定，不把旧稿哈希改成新稿。主 agent 不得提前将候选标 `done` 来制造前置通过。

#### 检查证据

`outline_draft` 与各轮 `outline_revision_N` 的 `checks.outline_candidate` 使用通用 `path/sha256/summary`，指向本任务实际输出的新候选；`outline_revision_N` 还须 `checks.issue_disposition` 引用真实意见处置依据，`inputs` 包含上一轮候选和报告。审读及复核任务的 `inputs` 同时包含对应候选与实际参考依据，`outputs` 是独立报告，`checks.outline_review` 指向该报告，并附如下结构（所有路径与哈希换成真实值）：

```json
{
  "path":"审稿与修订/S02-章目审读-v1.md",
  "sha256":"实际报告SHA-256",
  "summary":"本轮可写性结论与剩余影响",
  "candidate":{"path":"大纲/全书章目-v1.md","sha256":"实际候选SHA-256"},
  "verdict":"revise",
  "readiness":{"actionable":false,"timeline":true,"causal_chain":true,"author_boundaries":true},
  "issues":[{"id":"O1","category":"blocker","chapters":[3,5],"minimum_fix":"明确首笔收款前的生活缓冲和首单延迟时可执行退路","verification":"按离开至收款的行动时间线逐项核对可支配资源和退路"}]
}
```

`pass` 要求四项 readiness 全为真且无 blocker；不要求 `issues` 为空，风险和留白可继续追踪。第二轮复核仍为 `revise` 时，报告还必须有二至三个 `options`，每项包含 `id/description/cost`，是具体结构改法及对人物、因果、篇幅或阅读效果的代价，不能只写“继续修／暂停”。工具给出 `next_action=author_decision`，拒绝第三轮自动返修。主 agent 将这些方案交作者，保留全部原稿和分歧；作者明确选择该报告中的结构方案后，通过下节的 `outline-rescope` 合法接续新范围，不借换 ID 或开同义任务无限续审，也不直接放行存在硬阻断的候选。

最终接受的 `inputs` 必须包含当前候选、最后一份独立报告与作者确认依据；`checks.current_version` 绑定当前候选，`checks.author_confirmation` 引用实际确认记录并带 `candidate`、`source_quote`、`scope`。确认必须指向该版本，不用最初的写书委托、审读报告或修订完成回执替代。作者仅确认章目不自动扩大为正文授权；已有“确认章目后按卷写作”的授权则直接复用，不重复请示每章。最新审读已通过但作者明确要求修改时，按下文“审读通过后作者要求修改”重定范围，不要求作者先接受旧稿，也不把独立报告改成结构阻断。

`next_plan` 在最终接受后记录第一卷的章节范围、首章任务、交付粒度与首个正文回报节点，并细化下一合法 `chapter`／`trial` 阶段；资料待办只带影响当前行动的必要项。后续触发、里程碑及未授权保护见[协作流程](orchestration.md)“从章目确认进入第一卷”。

#### 达到两轮上限后的作者选择接续

第二轮复核已验收 `done` 且结论仍为 `revise` 时，主 agent 把该报告的具体 `options` 及代价交作者选择。作者明确选择其中一项后，将真实选择原话保存为本书不可变依据，由主 agent 核对其对应当前候选、最后报告及实际选项，再调用 `outline-rescope`：

```bash
python "$SKILL/scripts/taskctl.py" outline-rescope --book "$BOOK" --request /绝对路径/章目改定范围请求.json
```

```json
{
  "stage":"S02",
  "successor":{"id":"S03","title":"作者新结构方案章目"},
  "reason":"作者对两轮后剩余硬阻断选择了具体结构方案，按新范围重新规划",
  "verification":{"agent_id":"实际主agent标识","source":"真实作者选择与版本核验出处"},
  "choice":{
    "path":"创作约定/S02-结构方案选择.md",
    "sha256":"实际选择记录SHA-256",
    "source_quote":"作者对报告中具体选项的真实答复",
    "scope":"本次所选结构方案的实际适用范围",
    "option_id":"A",
    "candidate":{"path":"大纲/全书章目-v3.md","sha256":"最后候选实际SHA-256"},
    "report":{"path":"审稿与修订/S02-章目复核-v3.md","sha256":"第二轮报告实际SHA-256"}
  }
}
```

`option_id` 必须来自当前最后报告，不能自行补一个新选项或把泛泛“继续”当作选择；`source_quote` 须保留文件中实际可核对的原话。命令校验当前两轮复核状态、候选／报告／选择记录版本及主 agent 的核验申报，并将旧阶段标为仅阶段使用的 `superseded`：它表示“按作者新选择被后续范围取代”，是历史终止，不是通过。原任务的 `submitted/todo/done`、原稿、报告和未通过结论全部保留，不假验收 `outline_acceptance/next_plan` 或调用普通 `close` 来绕过硬阻断。

接续阶段只能是新的 v2 `outline`，不能是 `chapter` 或其他正文流程；新候选按新选择范围产出，仍须独立章目审读、最多两轮针对性返修及最终作者确认。作者选结构方案不等于确认尚未产出的新章目。只有有新证据的真实作者选择才允许重定范围，不能靠换 ID、重复使用旧选择或创建同义任务继续第三轮自动返修。旧历史、所选报告与选择依据保持可核验，接手者能看出为何结束旧范围及新范围的来源。每次重定范围须使用未被历史 `outline-rescope` 复用的作者选择记录路径；若已有唯一且完全未开工的未来阶段骨架，命令将其原样归档到旧阶段的 `outline_supersession.superseded_future_plan` 后移出活动阶段，以全新 ID 建立新章目阶段，不丢失计划或假验收；未来阶段已有输入、产物、检查、历史或验收依据等开工痕迹时拒绝转换，不删除真实工作。

#### 审读通过后作者要求修改

最新独立报告已验收 `done` 且为 `pass`、当前候选尚未最终接受时，作者可以明确要求修改该候选；初审、第一轮或第二轮通过后均适用。仍使用 `outline-rescope`，请求沿用上例，但在 `choice` 中填 `mode: "author_revision"`，省略 `option_id`，用 `source_quote` 保留真实修改原话、`scope` 说明本次修改范围，并绑定当前 `candidate/report`。例如：

```json
{
  "stage":"S02",
  "successor":{"id":"S03","title":"按作者反馈修改章目"},
  "reason":"作者要求修改当前已通过审读、尚未确认的候选",
  "verification":{"agent_id":"实际主agent标识","source":"实际反馈及版本核验出处"},
  "choice":{
    "mode":"author_revision",
    "path":"创作约定/S02-作者修改要求.md",
    "sha256":"实际反馈记录SHA-256",
    "source_quote":"作者本次具体修改原话",
    "scope":"本次修改的实际范围，不自动授权正文",
    "candidate":{"path":"大纲/全书章目-v1.md","sha256":"当前候选实际SHA-256"},
    "report":{"path":"审稿与修订/S02-章目审读-v1.md","sha256":"最新通过报告实际SHA-256"}
  }
}
```

默认省略 `mode` 或填 `option` 仍只适用于上节两轮后选择结构方案的分支，不能以作者修改模式绕过尚未解决的结构阻断。

反馈保存为本书单独的不可变记录，保留本次消息来源、日期、候选和报告版本；记录路径及内容哈希均不得复用此前 `outline-rescope` 的选择依据。作者只说继续、尚未答复或 agent 自己提出修改均不构成本分支授权；真实原话和是否明确修改由主 agent 核验，不能将复制旧选择换路径当成新反馈。

命令保留旧候选、通过报告及未验收任务，标记旧阶段 `superseded`，建立新的 v2 `outline` 阶段。旧报告的 `pass` 仅证明旧候选，不能为新章目放行；新范围仍须独立审读、最多两轮自动结构返修及对新候选的作者确认。新选择不直接授权正文，不假验收旧阶段；已规划后续阶段的保留与拒绝条件沿用上节。

### 独立整理与只读审稿

仅整理作者已有材料使用 `materials`，仅审查既有稿件使用 `review_only`，无需先完成创作方向访谈，不强制补设定、改稿或正式采用。`scope.checks.authorization/source_status` 引用实际本轮授权及材料范围，说明允许读取和写入的具体路径、产物及结束条件；已有具体任务指令可直接记录。`organize` 由资料 agent 执行，仅整理既有内容；`read_only_review` 由独立评审 agent 执行，原稿只读，输出具体阅读问题与证据。独立模式的额外调研等任务须直接依赖已验收的 `scope`。`materials` 可将既有正文／大纲只读保存为来源，整理结果只写资料目录，不向草稿区、大纲或顶层正式正文登记输出；`review_only` 只产出审稿与接续记录，不修改活动故事资料。独立模式不能添加构思、正文、试写、修订、专项创作或采用任务；发现未定创作矛盾只报告，新的创作任务另获授权后进入相应工作流。

新建项目或迁入缺失账本时，分别用 `novelctl init --workflow materials|review_only` 或 `taskctl init --workflow materials|review_only` 选择初始流程；默认仍为 `planning`。当前唯一 `S01` 还只是完全未开工的规划骨架时，可用 `plan` 提交 `{"id":"S01","workflow":"materials","reason":"真实本轮仅整理要求","verification":{"agent_id":"实际主agent","source":"真实作者指令出处"}}` 显式改派。原阶段完整保存在 `workflow_history`；已有任务输入、产物、检查、执行历史或已规划后续时拒绝改派，不能借此抹去未完任务。已开工阶段内的临时独立请求可增加有限额外任务并交付，原阶段保留真实未完项，不宣称已结项。授权仅到本次整理或审稿时，验收 `next_plan` 的真实 `end_reason` 后即可正常关闭独立阶段，之后可按新授权建立下一阶段。

### v2：在原任务中验收具体编辑责任

核心任务顺序不变，不为每条要求再建账本。v2 使用 `checks` 引用已读输入或已交付产物；每个值为 `{"path":"作品内相对路径","sha256":"文件实际哈希","summary":"本项判断、取舍或待办的简要依据"}`。指针必须出现在同任务的 `inputs` 或 `outputs` 中。几项检查可以引用同一份准备、评审或交接报告，但不能只复制“已检查”。

| 任务 | 必需 `checks` 键 | 验收内容 |
| --- | --- | --- |
| `scope` | `authorization`, `source_status` | 本轮真实授权、允许输入／输出路径、原文版本、缺口与终点；不补创作方向问卷 |
| `organize` | `source_status`, `handoff` | 实际整理范围、原文支持、未定矛盾及接续；无新增创作选择时仍说明 `creative_decisions.none_reason` |
| `read_only_review` | `reader_experience`, `editorial_findings` | 实际阅读版本、范围、独立性限制与有原文证据的审稿意见 |
| `direction` | `author_preferences`, `startup_mode`, `authorization` | 阅读目标、偏好来源与范围；资料方式的实际选择或有效免问记录；合作方式与本轮授权 |
| `concept` | `story_engine` | 持续选择、主故事承诺及长篇支撑风险 |
| `prepare` | `author_preferences`, `chapter_design`, `global_direction`, `source_status`, `prose_policy` | 本章约定；人物诉求、变化和详略；完整模式的三专项或轻量联合方案及已启用暗线依据、起伏安排、总编意见；关键设定支持范围；从约定提取的执行规则 JSON |
| `voice_trial` | `style_scope` | 两份候选的实际差异、作者已选比较范围、共同约束、待选择状态及后续阅读／选声路径，不预先确定采用声音 |
| `first_read` | `reader_experience` | 封存的自由阅读体验、阅读范围及隔离限制 |
| `review` | `editorial_findings`, `global_direction` | 分角色代入报告及全稿编辑核查、连贯性与阅读问题证据；跨章推进、重复、承诺与成长节点 |
| `revise` | `issue_disposition` | 重要意见如何修改、拒绝或按授权保留，以及代价 |
| `recheck` | `current_version`, `issue_disposition` | 当前稿的独立全文／增量复核与问题处理结论；受影响角色的代入复核 |
| `sync` | `source_status`, `handoff` | 完整模式三专项或轻量联合包及已启用暗线的正式更新与不可变依据；正文事实、推测与过期指令处理；当前进度、限制和待办 |
| `next_plan` | `global_direction`, `handoff` | 后续推进和连读安排；接续入口或授权终点 |
| `whole_read` | `reader_experience`, `global_direction` | 完整范围的实际阅读、结构及承诺兑现 |
| `structural_revision` | `issue_disposition` | 整体问题的实际处理或有依据的保留 |
| `whole_recheck` | `current_version`, `issue_disposition` | 当前完整范围的复核与重大问题处理 |

`draft`、`adopt`、`finalize` 沿用原有产物与机械门槛，不另堆检查键。`submitted` 和 `done` 都要有相应证据；脚本只核验结构、引用和版本，主 agent 仍须核对内容及真实派工。填写“总编已读”或 `summary` 不能证明实际阅读和问题已解决。

### 外部调研资料：落盘与复用

资料收集须交真实资料／调研子 agent，主 agent 只调度、与用户对话并验收，不亲自执行一轮检索收集。调研可由当前已合法开工的 `organize/prepare` 等资料任务承接；需独立调研时在同阶段加额外 `research` 任务，列清实际缺口、先查本地的范围、外部来源与归档验收条件。规划阶段的调研依赖已验收 `direction`，独立整理/审稿阶段依赖已验收 `scope`；章节/试写所需的独立调研排在 `prepare` 前，依赖已有真实前置（若有），并让 `prepare` 追加对调研的依赖，不反向依赖 `prepare` 形成环。其他阶段按真实使用先后列依赖，下游使用者须等归档任务验收。不强制每阶段查资料，不新增工作流或第二套资料账本；独立 `materials/review_only` 仍遵守各自允许的输入输出，`review_only` 查证只产出审稿记录，不借额外任务修改活动资料。

主题笔记和原始附件按[作品资料约定](story-records.md)同名小节当轮保存。首次归档和后续更新均登记真实 `outputs`；持续更新的主题笔记先保存本轮不可变内容副本，再通过该副本输出的 `material_files` 关联活动文件路径与哈希；固定副本须保留实际可复用内容及来源映射，不能只有文件清单。不能把会更新的主笔记直接绑成历史任务长期不变的证据。原始附件若冻结保存可直接登记输出，后续替换须保留旧版，或同样通过固定依据关联当前版。文件索引沿现有机制维护；归档依据应列实际新增/更新/复用文件及版本、未解缺口与补搜原因，不只写“已落库”。后续消费任务在 `inputs` 绑定已验证的不可变内容副本/资料包；冻结保存的原始附件可直接作为输入，不把复用伪记成一次新检索。确需直接绑定活动笔记时，其后变化会使对应任务及依赖失效，须按既有返工规则重开核查；`material_files` 不豁免 `inputs` 的哈希校验。

现有 `prepare/organize/sync` 的 `checks.source_status` 引用同任务输入/产物中的真实依据，说明本轮本地检索结果、直接复用与补搜原因、归档路径、支持范围、待核实/冲突及复查条件；无缺口且无需外搜时说明理由即可。额外 `research` 的验收也核对这些内容。`checks.handoff` 在适用任务链接资料索引与未解项。下游依赖归档任务验收，不能把聊天中的“查到了”当作准备完成；独立首读及角色材料仍按隔离范围派发。

脚本将 `参考资料/` 内的主题笔记和任意格式附件纳入产物登记，发现未登记或变更后未重新提交的文件时阻断执行；`material_files` 校验当前文件存在及哈希，保留固定历史依据。已有同义目录的文本记录沿通用检测，二进制附件须显式登记并核对版本。脚本不能判断网页结果是否全部落盘、来源真实性或语义是否适用，主 agent 须打开实际产物，并按关键命题抽验原文／来源、内容与支持范围后才验收；缺项或失实交回子 agent 补查，不以一个网址、文件名或哈希代替可复用资料。

### 对照试写的阅读与选声

`trial` 保留原核心顺序和字段，`voice_trial` 只负责交付同场景两份候选、版本与已选比较范围；尚未匿名阅读及获得选择时，验收不能写成“已采用声音”。主 agent 在同一账本的 `voice_trial` 与 `draft` 之间插入下列完整的额外任务对象，再 `render`；不得把核心 `first_read` 提前或重复创建。

| 非核心 kind 与示例任务 ID | 必需前置 | 产物与验收 |
| --- | --- | --- |
| `voice_first_read`，如 `S02.V01.read` | `S02.voice_trial` | 未参与候选写作的真实评审对两份候选匿名阅读；`inputs` 绑定候选及必要中性前文哈希，`outputs/checks.reader_experience` 保存封存反馈、实际阅读范围和隔离限制。反馈封存后才提供推荐理由或作者意图。 |
| `voice_selection`，如 `S02.V01.select` | `S02.V01.read` | 由主 agent 登记真实作者选择或有效免问依据；`inputs` 绑定候选、已验收反馈及作者决定，`outputs/checks.style_scope` 记录选中版本、代表片段、适用范围、理由和待验证项，`checks.creative_decisions` 按作者决定门槛填写并在开工前核验。 |

`draft` 保留原有 `S02.voice_trial` 前置，并追加实际选择任务 ID `S02.V01.select`；因此依赖关系为 `voice_trial → voice_first_read → voice_selection → draft → first_read`。两类新增任务一经安排都须走 `doing → submitted → 主 agent 核验 → done`，不能用 `not_applicable` 跳过。即使比较范围已获授权，也不能据此提前选择结果；作者尚未选择且无覆盖选声的有效免问依据时，选择节点保持待办／受阻，不能先出采用章稿再补决定。

候选阅读采用首读的中性输入与元数据检查；执行者的 `gate --neutral`／`--book-ref` 绑定实际 `voice_first_read` 任务，不指向等待章稿的核心 `first_read`。选择后最终章稿仍由满足隔离条件的上下文完成核心 `first_read`，旧 A/B 反馈只作比较证据。候选、比较范围或选择依据变化时重新打开受影响节点和下游，保留旧报告及决定历史。只比较到本场景，不自动推广全书；实际身份、匿名程度与作者原话仍由主 agent 对照宿主记录核验，技术测试不证明文学效果。

### 仅交候选与反馈的有限试写

作者只要同场景候选及独立反馈、不选声不采用时，完成本轮必要方向确认后，用 `plan` 建立 v2 `trial_only` 阶段并指定目标 `chapter`，不使用包含采用职责的完整 `trial`。它直接生成 `prepare → voice_trial → voice_first_read → next_plan`；保留作者决定、按完整／轻量模式的专项或联合准备及适用暗线准备、双端 gate、真实独立阅读和逐项验收。只允许 `voice_trial` 登记候选正文，其他节点输出准备、反馈和接续记录；不得添加选声、章稿、修订、采用或定稿节点，不能借额外任务扩大授权。

候选及反馈验收后，在 `next_plan` 记录真实 `end_reason` 即可关闭；以后新授权可另建 `chapter/trial` 或独立任务阶段。候选不因此变为正式正文；正式采用仍须满足完整章节、当前稿独立评审、作者选定与资料同步门槛。

若误用完整 `trial` 且尚未开始选声及后续章稿工作，可由主 agent 用 `plan` 显式收窄：

```json
{"id":"S02","workflow":"trial_only","reason":"实际作者指令仅交候选和独立反馈，不选声、不采用","end_reason":"本轮有限试写已交付","verification":{"agent_id":"实际主agent","source":"真实作者范围及验收出处"}}
```

收窄只接受当前未关闭的 v2 `trial`：准备、候选及独立反馈须已有效验收，无 pending；选声、章稿及其后续被移除节点必须完全未开工，不能已有输入、产物、检查或执行历史，也不得被保留节点依赖。原完整阶段保存在 `workflow_history`，已做工作保留，`next_plan` 按新范围重新验收。已有章稿或实际采用时拒绝转换，不能借收窄消除未完职责或异常产物。

### 角色评审任务与返工轮次

角色视角评审归入现有章节及定稿闭环，不新增阶段、`checks` 键或评审 schema。主 agent 在唯一 JSON 数据区按范围增加下列固定非核心 kind，再 `render`；三者必须有真实报告并验收为 `done`，脚本禁止 `not_applicable`。材料缺失或信息不足要如实报告；报告职责验收为 `done` 不表示人物行为已被认定合理，编辑须区分材料缺项与正文缺乏支持，必要时重开材料及受影响角色节点补做。确无适用关键角色时，由独立编辑在核心报告写明所查行为、范围及不适用理由，不先建角色任务再跳过。脚本不会自动判断角色覆盖，主 agent 仍须核对完整稿和实际派工。

| kind | 实际职责 |
| --- | --- |
| `role_materials` | 按角色和行为时点筛选材料，保存中性版本及由编辑持有的原件映射；不能让角色执行者先读秘密再自行忽略。 |
| `role_perspective` | 每个隔离上下文代入一个角色，提交行为、口吻、知情和可选行动依据，标明不足和不确定性。 |
| `role_editorial` | 在没有章节核心 `review` 的定稿阶段，独立编辑综合角色报告、完整正文及过滤映射，核查材料完整性和正文支持；不能由当前稿写作者代评。 |

宜在阶段细化时安排；执行中新补任务保留原状态和历史，`current_task` 同步为真实首个未验收项。每个新增节点用唯一 ID，不能复制核心 kind，也不因 kind 重复而省略定位。章节初评的材料任务依赖已验收的 `first_read`，各角色任务依赖材料，核心 `review` 保留原前置并追加角色任务依赖；各报告逐份走 `doing → submitted → 主 agent 核验 → done`。默认顺序派工；并行阅读仍串行落盘和立即提交，不能等整章完成后补账。`review.inputs` 引用已验收角色证据，`review.outputs/checks.editorial_findings` 保存编辑综合判断及实际版本。

**新增复核节点与重开既有节点分开处理。** 第一轮初评可用 `S02.R01.materials/A/B`，修订后新增 `S02.R02.materials/A/B`，后者依赖已验收的 `revise`，`recheck` 保留 `revise` 并追加 R02 角色依赖；不把 R01 材料节点改成依赖 `revise`，否则 `review → revise → R01 → review` 会成环。不同故事时点的材料也分别绑定，不能用新时点认知回头重评旧行为。

`recheck` 又要求改稿时，先冻结本次复核意见，重开稳定的 `revise` 及受影响下游；旧复核意见作为不可变文件输入交修订者，不能给 `revise` 反向追加 `recheck` 依赖。已经存在的后置 R02 节点可保留稳定账本 ID 重开执行，保留旧完成历史；新轮次必须换实际宿主任务／隔离上下文及不可变报告文件（如 `R03-A.md`），不覆盖旧报告、不只换哈希。新角色或新职责才另建新 ID，不能机械叠加一套相同职责并让已过期旧任务继续充当前置。初评及复核角色材料／稿件变化时同样重开受影响节点；保留依赖方向，按实际新输入、报告及独立编辑结论重新验收。

定稿的 `whole_read` 先完成完整独立阅读并封存。随后材料任务依赖 `whole_read`，分角色任务依赖对应材料，`role_editorial` 依赖全部本轮角色报告；`structural_revision` 保留 `whole_read` 并追加编辑综合任务依赖，其 `issue_disposition` 逐项承接角色发现。受影响角色的定稿复核任务依赖已验收的 `structural_revision`，独立编辑综合后作为 `whole_recheck` 追加前置，证据归入现有 `current_version/issue_disposition`。角色局部报告不代替完整全稿阅读。需要改正式正文时走下文 `defer` 及逐章采用同步，返回后重新整体阅读和角色核查，旧报告只作历史依据；无需改动也要有当前依据。

执行者只收到中性输入、版本 ID 与哈希；真实书根、内部稿件路径、含秘密的阶段／任务 ID 可放进书外临时 `--book-ref` 引用，由 `gate --book-ref 中性引用路径 --neutral` 在内部核验，执行者不得打开引用或完整账本。材料副本也必须筛查标题、各级路径、对象 ID、链接及注释等元数据，原件映射仅交独立编辑。具体协议及派工模板见[协作流程](orchestration.md)“派工元数据也须隔离”。门槛目标必须是本角色实际任务，不能指向正在等待本报告的核心 `review/recheck`。报告内容、角色覆盖、信息隔离和行为判断仍由主 agent 核验，脚本不认证语义。

### 专项任务与主文件版本

完整模式的三项基础专项职责使用固定的非核心 kind：`storyline_management`（故事线管理）、`hook_management`（钩子管理）、`curve_direction`（起伏曲线主导）；作者启用暗线后另加 `hidden_plot_management`（暗线管理），不需要时不建立这类任务。已安排的这四种 kind 均须以真实产物验收为 `done`，不得用 `not_applicable` 跳过；脚本禁止该状态。专项规划均纳入已有作者决定预检查：`checks.creative_decisions` 引用真实已选依据；三项基础专项无新增决定时明确 `none_reason`，暗线任务另须下述启用依据，不借专项任务名绕过决定性选择。模板不会自动生成这些专项任务或派工；主 agent 按下表插入任务及依赖。轻量模式不拆出三项重复任务，在现有准备／规划／同步节点引用联合包不可变依据并分别说明三个维度的判断；可延后不影响当前行动的细节。独立章目审读及硬风险门槛不因此省略。脚本不验证文学判断或真实身份，主 agent 须核对三位基础专项执行者及启用时的专职暗线执行者、实际内容与范围。

每个 `hidden_plot_management` 的 `checks.creative_decisions.items` 必须恰含一项 `topic: "hidden_plot"`、`value: "enabled"` 的有效决定，附 `id`、`record_id`、真实 `source_quote` 和 `scope`；`resolution`、实际问答及 `delegated/opt_out` 沿既有严格规则，检查仍须引用同任务已登记的输入／产物依据。可绑定已有有效启用决定，不表示每轮重问或产生新的情节决定；其他本轮决定照列。不能只用空 `items` 加 `none_reason` 开工，也不能使用 `disabled`、缺答或相互冲突的暗线决定；`gate/doing/submitted/done` 均检查此依据。该约束对兼容旧阶段中的这个新 kind 同样生效，不追溯改变其他旧 kind 的契约。

沿同阶段额外任务的现有方式安排唯一 ID、负责人、依赖和验收条件，不复制核心 kind，不增加第二本账本。各轮新增的专项调整任务用新 ID，旧产物与旧稿版本保留；新增任务后游标指向真实首个可执行的未验收项；`outline_draft=submitted` 的最终接受等待例外见章目小节。相同 kind 在同阶段有写前、采用后等多项，gate/update/submit 必须按唯一任务 ID（如 `S02.curve_pre`、`S02.curve_post`）定位，不能用 kind 猜测目标。主 agent 与执行者各自运行目标任务的 gate，再登记执行、提交和验收；专项 owner 可以读其允许的规划资料，不能接管隔离首读或角色任务。

| 工作位置 | 专项任务及核心步骤的衔接 |
| --- | --- |
| 新书规划 | `concept` 形成并验收已选构思后，故事线、钩子、曲线分别建立初始记录；曲线方案依赖前两份已验收依据，`next_plan` 保留原前置并追加三项依赖。未选新走向只作提案，不登记为有效设定。授权 `init` 只建待规划骨架，不算专项规划完成。 |
| 章节／试写准备 | 在 `prepare` 前安排三项本轮方案；故事线和钩子方案先完成，曲线方案综合二者后完成。`prepare` 追加专项依赖、引用三份不可变方案，再交写作者执行；旧书缺主文件时先在这些任务内核对并建立，沿用已登记同义主路径。 |
| 成稿评审与返工 | `review/recheck` 的独立编辑对照三项已验收方案、首读与当前稿评定实际效果；专项 owner 不能用自评代替它。仅有受影响项时新增对应调整任务：写前调整依赖已验收的 `review`，绑定已选调整并作为本轮 `revise` 的追加前置；修改成稿后的补充核对依赖 `revise`，绑定实际新稿并作为 `recheck` 的追加前置；每轮另取 ID，不能把旧写前任务追加下游依赖造成循环。 |
| 采用后同步 | 三项正式更新任务都依赖已验收的 `adopt`，各 owner 更新其主文件并提交不可变依据；`sync` 保留 `adopt` 并追加这三项依赖。一般资料 agent 汇总索引、摘要、变化记录及交接，运行 `finish` 后由主 agent 验收 `sync`。专项任务不提前把候选稿当正式实际，不在 pending 期间开下一轮写前任务。 |
| 后续计划 | `next_plan` 引用本轮已验收依据：已采用章节用采用后专项更新，规划阶段用初始方案，`trial_only` 用写前专项方案、候选及独立反馈，不产生正式实际更新。按授权范围记录到期钩子、各线下一推进、曲线 owner 的下一轮方向／待选项或本轮终点；详细下一轮方案仍待下一阶段合法开工。 |
| 全书定稿 | `whole_read` 完整阅读验收后，三位 owner 据全稿与独立反馈做总核查，`structural_revision` 保留 `whole_read` 并追加三项依赖。有结构修订时受影响 owner 新建更新任务、依赖 `structural_revision`，`whole_recheck` 保留其原前置并追加这些依赖；无改动也保留判断依据。需要修改正式正文时先用下文 `defer` 暂挂定稿，逐章完成采用与同步后返回重新全稿阅读及专项核查；不能用专项更新替代正文采用。 |

启用暗线时，在上表相应位置增加独立的 `hidden_plot_management` 节点：规划期依赖 `concept` 并作为后续三项方案的输入；章节／试写写前暗线方案先验收，故事线、钩子和曲线安排按实际引用追加其依赖，`prepare` 追加暗线依赖；独立 `review/recheck` 在首读封存后核对暗线实际效果。需调整时依上表方向增加本轮唯一任务 ID，采用后暗线更新依赖 `adopt`，`sync` 追加其依赖；全书核查依赖 `whole_read`，`structural_revision` 追加其依赖，修订后受影响暗线核查再作为 `whole_recheck` 前置。`next_plan` 和交接记录启用状态、待揭示项与下一触发。不能用暗线节点替代核心评审或三项基础专项，不自动给隔离首读／角色 agent 派发暗线内容；`materials/review_only` 不添加这类创作专项。脚本不从启用决定自动生成任务或验证依赖覆盖，主 agent 负责安排与核验。

三项基础专项及已启用暗线的主文件持续维护，历史任务不得将它们的活动路径及当前哈希直接作为长期 `inputs/outputs/checks`。每位 owner 在任务内保存本轮不可变依据副本（如 `历史版本/专项管理/S02-写前-钩子.md`），记录主文件路径、所据正文／方案、实际任务与 agent、当时计划／实际内容及版本；提交和后续任务读取、引用这些副本的真实哈希。专项主文件是当前内容入口，副本只作历史依据，不能再变成另一套有效计划。未验收本轮采用前持续保持旧正式实际，候选结论另列。

采用后本轮更新要记录正式章核对版本、三项实际结果或未分析／无变化理由、偏差及复查点，因此变化记录的 `clues/storylines/curve` 类别分别关联钩子、故事线、曲线 owner 的更新文件；启用暗线时，其正式核对依据沿 `storylines/clues/knowledge` 中实际受影响的类别关联，不新增所有作品必填类别。内容无新增不等于未检查。资料 agent 刷新索引后再计算 `finish` 所需活动文件哈希；长期任务证据仍引用已固定的专项副本。主文件正常续写不使历史快照过期，正文或依据真正变化时重新打开受影响任务、保留旧证据并复核，不能只换哈希。

#### 作者撤销已安排暗线的收尾

作者真实改选 `disabled` 后，立即停用被撤销的 `enabled` 依据，不再据它开工。主 agent 在唯一账本的 `history` 保留原完整任务快照、真实撤销决定及原因，原产物字节与正式承诺保留。仅对尚未完成的可选额外暗线节点保留 ID，改为非创作普通 `kind: "hidden_plot_closeout"`、`role: "materials"`、`status: "todo"`、`verification: null`，不修改核心任务或基础专项。当前 `outputs` 不绑定已撤销的未采用产物；原文件留在历史快照的 `outputs`，必要时用 `recover` 按 `excluded` 绑定真实撤销依据，不能排除正式事实或借此删除文件。

若撤销发生在 `adopt → sync` 之间且仍有 `pending_operations`，把这些收尾节点移到 `sync` 之后并依赖 `sync`；`sync` 仅移除被撤销的暗线依赖，保留 `adopt` 和其他专项前置，`next_plan` 追加收尾节点依赖。先实际完成其余专项、`finish` 及 `sync` 并清除 pending，再执行收尾，不把收尾伪装成 pending 期间获准的专项更新。

收尾任务正常经过 `doing → submitted → 主 agent 验收 → done`，实际提交冻结范围、影响核对与待决定事项的报告，不宣称原暗线专项已完成，也不用 `not_applicable` 跳过。报告只冻结与核对影响，新的剧情选择仍先问作者；撤销不抹去已采用正文及承诺，若需改正文走正式修订。已 `done` 的历史任务不改写，需要收尾时另加额外新节点；保留原 ID 的转换只适用于未完节点。

### 关键结果与实际操作绑定

新建 v2 阶段带 `result_gate_version: 1`，不能关闭或降级；旧无标记阶段保留历史契约，不补造操作。`submitted/done/check/close` 都复查关键结果，不能仅提交普通报告就宣称采用、同步或定稿：

- `adopt.operation_id` 对应本阶段、本章的真实采用档案，`outputs` 覆盖实际安装的正式章及其哈希，作品状态的采用操作编号也一致。
- `sync` 对应该操作的固定 `completion.json`，必须已真正完成 `finish` 且无 pending；`outputs` 引用本次变化记录或其固定 `synchronization.json` 副本。后续资料正常变化不改写这份完成凭据。
- `finalize.outputs` 绑定有效的全书定稿 JSON，记录的 `task_stage` 为本阶段，并通过当前完整章节清单、报告、章节检查与全稿复核覆盖检查。

当前阶段仍核对实际正式版本；已关闭阶段的操作档案保留为当时完成的历史依据，不强求当前改章后仍沿用旧采用操作。

### 开书停点：先收到答复，再开始实质工作

新建 v2 `planning` 阶段还带 `direction_gate_version: 1`。这是开书了解与授权的门槛版本，与 `workflow_version`、账本外层 schema 分开；其他工作流不增加此字段。它复用 `direction` 的三项检查和作者约定原件，不另建问卷或授权账本。

| 现有检查 | 新增决定位置 | 记录范围 |
| --- | --- | --- |
| `author_preferences` | `decisions.experience`、`decisions.style`、`decisions.length`；新决策门槛另需 `decisions.title` | 阅读体验；语言、节奏与详略；本次篇幅；作者选择的书名与历史状态 |
| `startup_mode` | `decision` | 先建资料、边写边补或混合；明确选择仅试写也可记录其有限路径 |
| `authorization` | `decisions.collaboration`、`decisions.work_scope` | 作者参与方式；本轮可以做到哪里、在哪里停 |

新建 v2 `planning` 另带 `hidden_plot_gate_version: 1`，在 `direction.checks.author_preferences.decisions.hidden_plot` 保存是否启用暗线的决定，`value` 只能为 `enabled` 或 `disabled`，其余来源、问答、范围及免问核验沿下述决定结构。缺答、`unresolved` 或其他值均不能验收方向；作者已有明确答复使用 `provided`，不重复问。`enabled` 只确认需要暗线，不批准具体秘密或情节。初始化的 `--hidden-plot-decision` 仅保存决定及按需建立空入口，不能代替方向任务验收；暗线决定后来补齐时，资料子 agent 在获准任务内更新作者约定、创建或沿用主文件并返回固定依据，由主 agent 登记。独立 `materials/review_only` 不启用这项方向门槛。

旧阶段不因缺暗线字段追溯失效；仅 `workflow_version: 2` 的当前未关闭 `planning` 阶段、且 `direction` 尚未验收时，可由主 agent 用 `plan` 显式提交 `{"id":"S01","hidden_plot_gate_version":1}`；该阶段须具备 `direction_gate_version: 1`，再保存真实答复。已验收方向不原地升级或改写历史。首次恢复旧书仍缺暗线选择时，主 agent 须在下一次新章规划、`prepare` 等实质创作前补问并保存真实决定；已有具体答复不重问，进行中的采用／同步机械收尾及历史已验收正文不追溯阻断。旧 v1 阶段不能加此标记，保留实际决定并以后续新 v2 规划阶段承接，不修改历史 `workflow_version`。不能关闭或降级已开启的标记。

每项决定使用相同结构，例如以下内容须有对应的真实作者答复，而不是 agent 预设：

```json
{
  "resolution": "selected",
  "value": "先建设支撑开篇的世界与人物资料，本轮不写正文",
  "question_quote": "先整理必要设定，还是边写边补资料？",
  "source_quote": "先把必要设定整理好，正文先别写",
  "scope": "本书开篇准备阶段"
}
```

`resolution` 为 `provided`（作者已主动给出具体决定）、`selected`（回答了实际选项）、`delegated`（问过后明确选择全部按推荐且不用询问）或 `unresolved`。前三者必须有非空 `value`、`source_quote` 和 `scope`；新决策门槛对 `selected/delegated` 还检查下节问答依据。仅书名另可用 `deferred` 表示作者明确暂缓定名，须有与未定项目匹配的 `work_id`、真实 `source_quote` 和 `scope`，不能带已选书名 `value` 或弃用名状态，初始化入口见[文件协议](file-protocol.md)。其他必需项仍为 `unresolved`、缺字段或仅有 `summary`，都不能提交／验收 `direction` 或进入依赖它的构思任务。待答期间保持待执行或 `blocked`，不先完成大纲再补账。

这些位置用于核对关键决定，不要求逐字段分开询问。已有具体答案直接引用；只有真实提问后，作者明确选择“全部按推荐且不用询问”，才可在该范围按推荐决定。泛泛“你定”“帮我写”“AI 主导”、只回答语言密度或本批全选 A，不能自动覆盖其他项目或未来选择。有限试写本身也不授权 agent 选择人物命运、冲突结局等决定性内容；先让作者选择，或取得上述唯一免问授权。单纯资料整理和不改变已选内容的机械维护无需全套开书问卷，但整理中发现的创作矛盾不能擅自定案。

旧规划阶段不因缺此字段被追溯判为从未完成。对于旧空骨架或 `direction` 尚未验收的活动阶段，继续实质工作前由主 agent 用 `plan` 显式补上开书门槛，再补真实答复：

```json
{"id":"S01","direction_gate_version":1}
```

该操作保留已有任务、历史和 `workflow_version`，不补造作者批准；门槛不能降级。已关闭阶段或已经验收的方向不能借此重写历史，须在当前合法任务范围重新核对实际约定，必要时另建规划阶段；原有草稿保持原状。未通过验收的旧方向仍不能因新版章节阶段已建好而被跳过。

### 决定性选择：作者选定后才执行

新建 v2 阶段带 `decision_gate_version: 1`，涵盖全部工作流；它与仅用于规划的 `direction_gate_version` 分开。旧阶段无此字段仍保留历史校验，不能原地补此标记追认旧批准；后续新阶段启用新门槛，旧活动任务继续时也须遵守当前作者决策规则，不得沿用已撤销的泛委托。脚本不提供关闭或降级新门槛的请求。

决定性选择包括且不限于书名及恢复弃用名称、作品方向与结构、视角与风格、承重世界规则、人物成长/命运/关系、冲突解决方式及代价、关键转折、秘密揭示、伏笔兑现和结局。推荐不是决定；待选内容只能作为供选择的提案，不能先写成执行大纲、有效设定、场景安排或正文。已有有效具体选择无需重问；照案执行和不改变创作选择的技术修错不逐词请示。

新门槛下，`selected` 决定另需非空 `question_quote`，与 `source_quote` 中的实际答复对应；`provided` 保留作者主动给定的具体选择。`delegated` 必须另含以下记录，两项布尔值都为真实的 `true`：

```json
{
  "question_quote": "实际问过的全部推荐免问选项，及其所指范围",
  "answer_quote": "作者实际选择全部按推荐且不用询问的答复",
  "scope": "明确生效的作品、阶段或推荐批次及例外",
  "all_recommendations": true,
  "no_further_questions": true
}
```

此对象放在该决定的 `opt_out` 中，不另造授权账本。主 agent 核对实际问题、选项映射与答复：选择“全部推荐”未同时免后续询问，不能申报此模式；对本批的许可只对本批生效，不迁移到新作品或新范围。作者撤回或新反馈优先，后续任务不得引用已失效许可。字段与布尔值仅是可验证的申报，不会替代真实来源语义核对。

`concept/prepare/revise/next_plan/structural_revision` 的原任务增加 `checks.creative_decisions`。它仍用 `{path,sha256,summary}` 引用作者决定主记录或其不可变副本，附本轮 `items`；每项含 `id`、`topic`、`record_id` 及上述决定的 `value/resolution/source_quote/scope` 和适用的问答/`opt_out`。同一已选决定可引用原记录，无须再问；新增或改变内容必须有对应新选择或有效免问依据。无新增决定时使用 `items: []` 加非空 `none_reason`，主 agent 对照实际方案审查，不能用空列表掩盖新选择。

这些任务在写前运行 `gate` 时即检查本任务的 `creative_decisions` 和所引文件的当前哈希，而非等写完提交才查。主 agent 可先用 `update` 在尚未验收的任务登记真实作者输入及此检查；这只登记已有选择，不生成故事方案。完整输出和其他编辑检查仍按正常提交／验收阶段提供。门槛未过时，停止依赖该决定的工作并回到对话给作者选项；不能改为另一任务名先写出来。脚本无法识别是否漏列决定，执行者与主 agent 都须对照实际内容核验。

书名已选决定还需 `prior_status: proposed|active|retired|rejected|unknown`，并与作品状态中的当前书名完全一致。目录名、素材标题或历史候选均不是作者选名证据；`retired/rejected` 另需非空 `history_source` 和 `reuse_confirmation`，其中 `acknowledges_retired: true`、`answer_quote` 必填。作者主动明确恢复（`provided`）时，`source_quote` 与 `answer_quote` 保留具名恢复原话，不要求捏造提问或再次询问。`selected/delegated` 则须实际 `question_quote` 点明具体旧名及曾弃用事实；单项答复明确该名，或通过 `selected_title` 与真实问题的选项映射指向它（如作者只回 A，`source_quote` 与 `answer_quote` 均保留 A，不能改写成具名原话）。若对这批明确展示的推荐选“全部按推荐且不用询问”，`opt_out.question_quote` 也须点名该旧名，复用确认的答复须与 `opt_out.answer_quote` 一致，不能用未提旧名的泛许可复活它。

新建作品在创建目录前核对已选书名决定或作者明确暂缓定名记录；中性工作标识不冒充书名、不放宽弃用名复用规则。CLI 及保存入口见[文件协议](file-protocol.md)。连续采用 `continuous` 只涉及何时采用稿件，不赋予决定人物走向或冲突解法的权限；稿件采用授权与创作选择须分别满足。

总编的章前判断、写后判断和阶段连读由 `prepare/review/next_plan` 承接。已触发而未完成的必要连读须登记并处理，再继续依赖它的章节；不能只把总编写在角色名单里。触发与角色独立性见[协作流程](orchestration.md)。

只详细安排当前阶段和下一阶段。阶段结束前，把 `next_stage` 指向已经生成完整必做任务的下一阶段，再验收 `next_plan`。本次授权仅到候选及反馈时使用 `trial_only`（已误建完整流程时按上节显式收窄）；作者要求结束或整书工作结束时，可在适用工作流职责实际完成后用真实 `end_reason` 表明本轮终点，不为满足计划要求擅自扩写，也不以结束理由豁免已开始的任务。关闭阶段只移动接续入口，不执行下一阶段，也不扩大作者授权。

改变 `next_stage` 或 `end_reason` 会重新打开已验收的 `next_plan`，须核验新的安排后才能关闭阶段。本轮结束后获得新的继续授权时，可用 `plan` 新建或选择已规划阶段；只有此前当前阶段已关闭，命令才会把游标移过去，保留旧结束理由而不自动执行新任务。

已关闭阶段保留历史状态和证据入口，不把旧版本当作当前新稿的完成证明。关闭章节阶段的正式采用产物可通过本阶段真实操作的已验证不可变档案核验当时字节，避免当前章后续合法改名或重写破坏历史；仅限与操作的原目标路径、章节、阶段及哈希完全对应的采用输出，其他输入、报告和资料证据仍按原路径严格验证。修改此前已关闭阶段的章节时，新建对应章节修订阶段，引用旧成果并重新核查当前版本；当前阶段内返工则重新打开受影响任务。

## 输入、证据与返工

输入与产物使用作品内规范相对路径及实际 SHA-256。未登记／越序检测覆盖所有作品资料目录，包括人物、世界、连贯性、摘要、关系、资源及自定义目录；索引、技术管理文件、历史档案和内容未改的初始化空骨架按各自规则处理。作者原有材料通过真实 `recover author_input` 登记，不凭目录名免检。完成任务必须有当前有效的产物证据；`next_plan` 检查账本内的下一阶段或结束理由，不要求创建重复计划文件。不要把账本自身或不断变化的 `创作约定/作品状态.json` 作为任务哈希输入，否则更新记录本身就会令任务失效。历史稿、首读原件和采用前快照按现有版本规则保留。

持续更新的资料主文件不直接成为历史任务长期哈希证据：先保存当轮不可变内容副本，将该副本列入 `outputs`，可附 `material_files: [{"path":"人物/当前人物.md","sha256":"本轮当前副本哈希"}]` 关联本次维护的活动文件。提交或改变声明时核对活动文件真实哈希；历史任务继续绑定不可变副本，后续合法维护另交新副本和新声明。不能通过该字段预注册未来产物，也不能借它声明正文、草稿、大纲或审稿报告，这些仍须按实际任务独立登记。索引和状态更新不作为故事产物。采用后 `sync doing` 期间，采用请求中的变化记录及其 `updated_files` 可暂时关联本轮资料，`finish` 校验并封存后由固定完成凭据承接；已验收同步后来重开时，凭据所证明的旧资料版本仍保留历史来源资格，但不恢复任务完成状态，新改资料仍须重新登记。不因此允许新创作。

所有来源只限当前作者指定书根；不能把其他由本 Skill 创作的书登记成输入、候选、历史证据或恢复来源，复制到本书也不改变来源。恢复核对文件沿用本书作者约定、既有接续或实际异常说明，不新建另一套任务账本。任务证据可验证路径及版本，是否跨书须对照真实来源核验；单书边界见[文件协议](file-protocol.md)。

`check` 检查当前阶段的固定步骤、依赖、已验收证据和显示一致性，正常的未开始任务不等于检查失败。`gate` 检查目标步骤的前置依赖闭包及目标任务自身已登记输入的当前哈希，未验收、证据缺失或哈希过期时不能继续；执行门槛还检查实质产物是否与任务对应。存在未完成采用操作时，先完成当前采用的行政登记、采用后专项更新与同步，或恢复现场，不重开起草、试写、修订等新创作。启用执行门禁的采用和同步任务须先登记 `doing`，写命令不能代替开工登记；关闭阶段前也须处理未登记或越序产物。唯一行政接续例外是来源、原话与版本仍有效且明确归属 `next_stage` 的 `held_output`：可以关闭当前已验收阶段以移动恢复游标，但下一阶段的普通 gate 仍阻断创作，须继续按 `recovery_only` 顺序补齐真实缺项；未知产物、来源失效或归属不符不适用。主 agent 派工前运行，执行子 agent 在写入实质产物前也自行运行同一门槛；失败只返回缺项与原状态，不能先写后补。首读者和角色视角评审者只运行绑定各自实际任务的中性 gate，元数据越界时通过 `--book-ref` 隐藏真实书根及账本 ID，不读取引用文件或账本内的创作信息；该模式不回显原始异常或内部证据路径，主 agent 用普通 gate 或 check 查看详细诊断。当前阶段未关闭，不得跳到已规划的未来阶段执行。

输入或产物变化时，检查报告失效任务及受影响的下游任务；主 agent 将对应任务重新打开，保留旧状态、旧证据和失效原因，再更新实际新输入、修订及复核证据。重新打开已完成任务会连带作废其已开工、已提交和已完成的下游验收，曾验收为 `not_applicable` 的条件项也须重核；旧状态、旧证据及当时仍存在的登记产物保存在历史，当前证据清空并统一设置重开标记；这些下游须重新核对当前输入，再用 `update status: doing` 显式提供本轮 `inputs`（确无文件输入时可为空列表）和非空 `reason`，清除依赖变更重开标记后才能提交、验收；不能沿用旧 `doing/submitted` 状态或用 `recovery_only` 恢复完成。已登记的旧产物原样保留为待复核来源，不代表已完成，也不应反过来阻断上游返工；未登记、变更或尚无来源的文件仍走正常恢复门槛。只复核影响范围；原首读保留为旧稿阅读证据，不伪称读过意图的评审者又完成了盲读。

直接更新已验收任务的证据、操作号或处理理由也必须提供新的主 agent 验收依据，并会作废已开工、已提交和已完成的下游；不能用旧验收、旧开工状态或只替换哈希保留后续进度。

首读评审只能收到中性任务标识、必要正文与前文、哈希、读取规则和已经核验的依赖结论，不能收到整个任务账本或包含未来秘密的阶段计划。相关计划与意图只交资料核查/全稿编辑，不交角色视角评审者；后者即使位于 `review/recheck` 阶段，也只接收对应故事时点的角色材料和中性门槛，不打开完整账本或普通诊断。

## 命令与执行顺序

命令中的 `SKILL`、`BOOK` 使用真实绝对路径，请求文件使用实际路径。主 agent 是行政账本的唯一写入者：直接执行 `init`、`plan`、`update`、`submit`、`outline-revise`、`outline-rescope`、`recover`、`defer`、`render`、`close`，负责批准状态变化并统一回读。资料／创作／评审子 agent 只返回本任务实际产物与依据，不自行写同一账本；正文、资料和采用同步仍由相应子 agent 执行。主 agent 可批量核对一组已返回产物，但每个依赖启动前必须完成其前置验收。请求 JSON 优先保存为临时文件，避免 shell 转义；这些请求不构成第二份任务账本。下列是 Bash 变量示例；Windows PowerShell 请用带引号的实际路径。`python` 须为 Python 3.9+，Linux/macOS 可替换为 `python3`，Windows 可替换为 `py -3`。

```bash
python "$SKILL/scripts/taskctl.py" init --book "$BOOK"
python "$SKILL/scripts/taskctl.py" plan --book "$BOOK" --request /绝对路径/阶段请求.json
python "$SKILL/scripts/taskctl.py" update --book "$BOOK" --request /绝对路径/任务请求.json
python "$SKILL/scripts/taskctl.py" submit --book "$BOOK" --request /绝对路径/提交请求.json
python "$SKILL/scripts/taskctl.py" recover --book "$BOOK" --request /绝对路径/恢复来源请求.json
python "$SKILL/scripts/taskctl.py" defer --book "$BOOK" --request /绝对路径/定稿改章请求.json
python "$SKILL/scripts/taskctl.py" check --book "$BOOK"
python "$SKILL/scripts/taskctl.py" gate --book "$BOOK" --stage S02 --before review
python "$SKILL/scripts/taskctl.py" close --book "$BOOK" --stage S02
python "$SKILL/scripts/taskctl.py" render --book "$BOOK"
```

阶段请求示例：

```json
{"id": "S02", "title": "第一章试写", "workflow": "trial", "workflow_version": 2, "chapter": 1}
```

新增后先为当前阶段指定下一阶段，例如用 `plan` 提交 `{"id":"S01","next_stage":"S02"}`，再验收当前阶段的 `next_plan`。已有阶段的工作流和目标章号不能改名换意，应新建阶段并说明调整。

任务提交示例，路径和哈希须换成真实产物：

```json
{
  "stage": "S02",
  "task": "first_read",
  "status": "submitted",
  "inputs": [{"path": "草稿与备选/第一章-v1.md", "sha256": "实际正文SHA-256"}],
  "outputs": [{"path": "审稿与修订/第一章-首读.md", "sha256": "实际反馈SHA-256"}]
}
```

主 agent 核验后直接提交该任务的 `status: done`，附 `verification: {"agent_id":"实际主agent标识","source":"真实验收记录或上下文出处"}`。不需要返工时，意见处理任务也需有可追踪的处理依据，不直接跳到采用。

上例只展示通用字段；v2 首读提交还须有 `checks.reader_experience`，引用同一首读报告及真实哈希，并写实际反馈摘要。其他任务按上表填写。`submit` 请求与 `update` 相同，但省略 `status`（或只允许 `submitted`），一次登记输入、产物和检查，不自动验收为 `done`。收到产物应及时提交并更新接续说明，不留到多轮写作后补账。

### 确定性回读与写后恢复

使用正式解析工具读取受管 JSON，不用正则、长 `python -c`、Windows Bash 命令替换或另存一份账本来猜状态：

```bash
python "$SKILL/scripts/taskpeek.py" --book "$BOOK" --stage S02 --task S02.outline_review --verify
```

`--task` 可重复，省略时返回该阶段各项；省略 `--stage` 默认当前阶段。只读回报 `current_stage/current_task`、原始任务记录和哈希／索引核对结果；`--verify` 对任务 `inputs/outputs/checks/material_files` 及嵌套候选一次批量核对，同一路径不反复散落计算。索引维护沿用资料子 agent 的 `novelctl index`，刷新后再计算依赖索引的真实哈希，不给每次状态更新重复做全书归档。

写命令已经返回成功而子任务最后的断言或回读失败时，先由主 agent 运行 `taskpeek --verify`；`read_ok=true` 表示账本已读取，即使 `ok=false` 也可能只是某项验证失败，先看实际状态、版本与错误位置。已存在预期 `submitted`、输出及检查哈希时保留该提交，只修复回读或明确的索引缺项；不能重复提交、覆盖候选或重跑已完成写稿。`read_ok=false` 或写入结果不确定时只读恢复，确认现状后才决定是否需补写。`taskpeek` 验证物理证据，不代替 `taskctl gate/check` 的 DAG 与作者授权判断。

三个关键节点：

1. **采用正文**：`chapterctl adopt` 自动检查对应 `trial` / `chapter` 阶段在 `adopt` 前的任务；`recheck` 的输入须包含实际采用草稿及哈希，产物须包含当前评审文件及哈希。采用请求可用 `task_stage` 指定阶段，未提供时只能匹配唯一适用阶段。若原操作停在 `prepared`，先由资料子 agent 按文件协议运行 `chapterctl resume`，核对原备份、当前现场和原有门槛后续办同一操作；普通 gate 不因恢复入口而放宽，不重新 `adopt` 或手改 pending。这是原已开工采用的机械恢复：主 agent 派前只读核对原任务与固定档案，执行子 agent 的 `resume` 在任何写入前运行恢复专用门槛；不要求先使普通 gate 的 pending 诊断变为通过，也不据此开新创作。
2. **关闭资料同步**：采用命令成功后，验收 `adopt` 任务，记录返回的 `operation_id` 及正式章节路径、哈希；再运行 `chapterctl finish`，它检查 `sync` 的前置已验收。`finish` 成功且资料核验完成后，才把 `sync` 验收为完成，避免要求同步前先勾同步完成。
3. **全书定稿**：`bookctl check` 检查 `finalize` 前置任务及当前完整正式正文的版本覆盖；通过并核验语义及授权后，才验收 `finalize`。`bookctl manifest` 获取清单时无需先完成定稿任务。

`close` 要求阶段必做项全部验收、条件项正确处理、下一阶段计划或本轮终点有依据，且没有未完成的机械操作。任务文件更新后按文件协议刷新索引；它不替代 `chapterctl finish`、`bookctl check` 或作者决定。

### 定稿期间需要逐章修订

`finalization` 的全稿阅读或专项总核查若发现必须修改正式正文，不把未完成定稿勾完，也不直接开未来章。主 agent 用 `defer` 暂挂当前定稿并转入一个正常的 `chapter` 修订阶段：

```json
{
  "stage": "S10",
  "revision": {"id": "S11", "title": "处理全稿核查指出的章节问题", "chapter": 3},
  "reason": "实际全稿核查指出的改章范围与依据",
  "verification": {"agent_id": "实际主agent标识", "source": "真实核验及调度记录"}
}
```

只允许当前未关闭定稿阶段：`whole_read` 及已有完成项必须仍有效，`finalize` 尚未验收，无 pending 或进行中／待验收任务，所有既有产物已合法登记。仅有定稿阶段未关闭时创建默认 v2 修订章；若已有唯一下一阶段，只能复用请求指定、章号相同且从未执行的 v2 `chapter` 阶段，其作者决定和执行门槛均须启用。其他未来计划不会被静默删除或越过。

命令保留定稿各任务的原状态、证据及暂挂理由于历史，清空其当前证据并全部重开为待执行，将修订章排到定稿之前；修订章关闭后返回定稿。修订章仍须按规划模式提供三项或联合写前方案、独立评审、作者决定、正式采用及专项同步，`next_plan` 指回已暂挂的定稿阶段。返回后重新完整阅读、专项核查与复核，旧结论只作历史依据，不能继续支持新稿定稿；需再改另一章时重复此路径。若存在未验收产物或同步中断，先按原流程处理真实状态，不用 `defer` 洗成历史完成。

## 新书、旧书与交接

新建作品默认生成 S01 规划阶段及任务文件，作品状态中的 `task_management: true` 表示任务门槛已启用，丢失任务文件不能绕过检查。旧作品没有该字段和任务文件时保留机械读取、恢复和工作稿导出能力；继续创作前由主 agent 用 `taskctl init` 迁入，任务文件一旦存在就启用相应门槛。

迁入时从真实已有成果恢复任务及证据，不补造过去不存在的派工和验收。无法证明的步骤保留为待完成；已采用旧章保持原文，按任务需要安排补查。旧阶段缺版本按 v1 校验，不直接升级它来追写历史；新阶段默认 v2。阶段版本不能就地更换，修订或升级后的工作用新阶段承接。仅当账本所有已有阶段都是 v1，且提供真实的 `compatibility_reason` 时，`plan` 才允许显式创建兼容 v1 阶段；已有 v2 阶段的项目不能降级。不得用兼容入口为新创作逃避 v2。`pending_operations` 仍是采用/同步中断的恢复依据，优先恢复实际操作，再核对任务状态，不能反复采用同一章。

旧活动阶段尚未关闭时，继续按原版本恢复，利用已有产物补做真实缺失的检查；可提交 schema 2 当前稿独立评审，并按新规范人工核对正文机械报告，但不能声称已自动获得 v2 门槛。当前阶段依真实结果完成并关闭后，下一阶段默认 v2。不能跳到未来阶段、补造历史验收，或为迁移而重写已有稿件。

接续说明只链接当前阶段、当前任务、受阻事项和下一步，避免复制整份任务状态。新 agent 每次开始、派工、采用及阶段收尾前读取任务入口，对照实际产物和脚本检查恢复，不把聊天计划当成唯一进度。

### 产物与任务脱节时的执行阻断及恢复

新建 v2 阶段默认 `execution_gate_version: 1`，不能关闭或降级。旧当前阶段尚未关闭时，继续实质工作前由主 agent 用 `plan` 请求 `{"id":"实际当前阶段","execution_gate_version":1}` 显式开启；保留原工作流版本、历史和待办，不追改已关闭阶段。开启执行门槛不表示任何任务或旧稿已经验收，也不能手移游标越过未关闭的前序阶段。

原 `warnings` 仍帮助定位，但启用执行门槛后，未登记、来源未核实或越序产物是 `check` 的失败项，也阻断实质任务 `gate` 及开工／提交／验收。脚本识别 `草稿与备选/`、`审稿与修订/`、`大纲/` 三类目录中除索引外的 Markdown、TXT、JSON，不只按章号文件名识别；改名或挂进任意任务 `inputs` 不能洗成合法进度。该机械扫描不自动识别其他目录的全部语义产物，主 agent 仍须核对实际派工与文件。正常产出须先合法登记 `doing`，返回立即提交当前路径与哈希；`todo/blocked` 不能提前挂新产物来替代开工。前置未验收时，后续依然不能开始。

发现“已有第一章或后续版本，游标仍在方向／准备”时，先停创作，保留全部原文件。只读核对真实作者输入、宿主派工与批准、版本及操作记录，再由主 agent 用 `recover` 保存来源与处置；命令只向同一本任务账本追加 `artifact_recoveries`，不改稿、不改任务状态、不补造历史开工或批准。每项结构为：

```json
{
  "artifacts": [{
    "path": "草稿与备选/已有稿.md",
    "sha256": "已有文件当前哈希",
    "classification": "held_output",
    "task_id": "S02.draft",
    "source": {"path": "创作约定/已有来源核对记录.md", "sha256": "核对记录当前哈希"},
    "source_quote": "核对记录中实际存在的来源或处置原话",
    "scope": "当前书已有候选稿的恢复核对，不授权续写或采用"
  }],
  "verification": {"agent_id": "实际主agent标识", "source": "真实核对依据"}
}
```

`source` 是另一份本书现存文件，原话须能逐字找到，不能拿稿件自证来源；引用真实作者约定、接续或异常记录的不可变版本，避免后续正常扩充资料使恢复证据过期。三种分类只描述事实与处置：`author_input` 是经核实的作者原有输入，不赋予新增创作权限；`held_output` 是已经产生、待按真实前置顺序核验的候选产物，须关联实际任务；`excluded` 是有真实处置依据的封存不用文件，不删除原稿，也不得再作为活动任务的输入或产物。分类及引用语义仍由主 agent 对照真实记录核验，不能自写一句“作者输入”来通过。

恢复期间只做行政登记和真实补查。确需在阻断状态提交或验收已经存在的证据，可用 `update/submit` 的 `recovery_only: true`，附非空 `reason` 与真实 `verification`；它不允许 `doing`，只接收已知或已核实恢复的文件，仍检查前置依赖、作者决定和相应验收证据，不能凭此创作、吞入未知旧稿或跳过缺失步骤。没有真实已完成的前置，就保持待办：请作者补选择，或凭真实处置先封存不用越序候选，再通过正常门槛补做工作。对应候选提交／核验及缺项恢复后，重新检查才能继续；不会因文件存在自动 `done`。

旧阶段未开启门槛时的 `warnings` 仅是线索，不证明已经执行，也不允许绕过当前规范。无论版本，已有草稿不要重复起草，已读 v2 不冒充已读 v3，无证据的验收保持待完成；不能删除异常文件或依赖来消除问题。文件或恢复来源变动后重新核对，不能仅改哈希沿用原验收。

当时实际使用的资料与当前继续执行的约束分别保留。需要长期引用的输入先保存不可变版本或指向已验证历史副本，再登记哈希；后续资料改变时，保留旧证据并为当前约束重新核查。不要为消除告警删除依赖，也不能仅更新哈希沿用原验收。历史阶段不补造新事实，当前修订用新任务承接。
