# 协作与执行流程

入口规则见 `SKILL.md`；按本次操作阅读下列对应小节，不要求每章通读本文件。已有宿主与流程未变时，直接查当前任务相关规则。

## 1. 宿主适配与身份

先用宿主实际提供的子 agent 工具。`agents/openai.yaml` 仅是 Codex 界面元数据，其他宿主直接读 `SKILL.md`，不把它当通用交互或派工入口。常见能力是 spawn、send input、wait/result；名称不同不影响工作。不要把工具调用协议写死成某个平台唯一依赖。每次保留真实任务返回的 agent 标识及任务标识；同一个实际 agent 换任务名仍不算独立评审。宿主只支持运行中 steer、已结束任务不可续聊时，新派真实子 agent，转交上一轮产物、输入版本和阅读范围，不声称还是同一评审者。只有实际的新上下文且未接触创作信息才能标首读隔离；读取旧意见的新评审应如实标为复核。

结果通过宿主原生的子任务完成/结果通道收集；子 agent 完成写入后直接以最终回复返回文件与证据。不要用面向其他用户或一般会话的发消息工具代替子任务回传。若某条消息触发额外审批，保留其真实状态，不重试或绕过；已有产物可只读检查，之后按宿主允许的原生派工与结果通道执行独立任务。

主 agent 负责沟通、调度、主动编辑建议与验收。本规范中的“写”“修改”“登记”“归档”“运行写命令”均由被派工的子 agent 执行。资料任务可批量承担文件建档与机械搬运；创作任务承担正文内容修改。主 agent 可以读文件、核对哈希、运行 check 或测试性只读命令，须解释独立意见与方案代价，但不替子 agent 写产物或用自身判断补缺失评审。

**全局总编是持续职责，不是永久会话。** 由未参与当前稿写作的真实子 agent 承担，写前检查章际方向，评审时检查实际效果；可与独立评审的资料核查合并承接。写前总编会接触计划，因此不能再冒充该范围的盲读者；首读者只有封存反馈后才可承接知情的总编核查。两者可为不同实际 agent，不向首读泄露计划。总编不改被评正文，资料子 agent 保存其短结论、输入范围与待办；新会话可依文件接任，不另造第二本任务账本。

在当前环境没有子 agent 能力时停止创作执行，说明需换到具备此能力的工具；不要求作者同意主 agent 代写。若子 agent 中途失败，重新派实际任务、保存失败状态与有效产物，不虚构一个成功角色。

### 单书读取边界

写一本书时，只以作者明确指定的当前作品绝对路径为书根，读取本书任务所需文件与 Skill 的规则、脚本；不为找素材或恢复现场遍历作品库、父目录或相邻作品。尚未知道书根时先请作者指定，不先搜索所有书再筛选。外部现实资料、作者经验或非本 Skill 作品的参考材料，须符合当前任务的真实授权及读取范围。

**禁止读取其他由本 Skill 创作的书的内容。** 包括正文、草稿、大纲、人物与世界资料、摘要、评审、语言样本、历史快照及压缩包，也不调用跨书检索、向量库、共享记忆或旧会话提取其内容。不得以“找风格例子”“借用结构”“参考以前成功经验”读取；改名、复制进当前书、转成摘要或由其他 agent 转述，均不改变来源。已知或标明来自其他 Skill 作品的材料不打开，来源存疑且可能越界时先确认来源。全部推荐免问、AI 主导或一般资料授权不能放宽这条边界，不自行设置跨书参考开关。

主 agent、写作、资料、总编和评审各角色均受此约束。每次派工写明唯一书根、允许读取的文件或本书内搜索范围、获准的外部来源，以及禁止跨书读取；返回实际输入清单。不同作品不复用已携带另一书内容的 agent、会话、缓存或交接材料，也不把另一书摘要注入新任务。已发现上下文含另一书内容时，停止本书创作和评审，说明污染来源与受影响范围但不复述其内容；换用只接收本书必要资料的干净上下文重新接手。宿主无法隔离时保留现场并停止创作，不能按普通评审降级继续；这与下文仅针对本书创作意图的首读隔离是不同边界。

### 现场任务与阶段

主 agent 每次进入现场先读 `创作约定/任务计划与验收.md`，对照正文、评审和 `pending_operations` 恢复真实进度。账本受管标记内的唯一 fenced JSON 为权威数据，阶段和任务 checkbox 由脚本生成，不手工勾选另一套状态。记录格式和请求文件见[任务管理](task-management.md)，不猜测 JSON 字段；交接说明只链接当前任务入口，不复制整本账本。

新书通过 §3 的开书停点后，才按本轮授权建书；`novelctl init` 会创建 `S01` 的 `planning` 阶段。旧书缺账本时，先派资料子 agent 执行 `taskctl.py init --book BOOK` 迁入，依据真实旧产物补任务与证据；无法证明的旧步骤保留待办，不追认成全部执行。首次建书或账本迁入完成后，再按任务门槛派工；引导操作的边界见[任务管理](task-management.md)，不借建档提前写实质内容。

阶段由资料子 agent 用 `taskctl.py plan --book BOOK --request JSON文件` 按内置工作流生成必做任务，再细化范围、依赖、输入哈希和验收条件：`planning` 包含 `direction/concept/next_plan`；`chapter` 包含 `prepare/draft/first_read/review/revise/recheck/adopt/sync/next_plan`；`trial` 在 `prepare` 后增加 `voice_trial`；`finalization` 包含 `whole_read/structural_revision/whole_recheck/finalize/next_plan`。作者契约、总编、正文规范和资料反查的验收证据纳入现有步骤，不为每个检查新开一条流程。检查类别、工作流版本与证据字段以[任务管理](task-management.md)为准，不猜测 schema。条件查阅、外部反馈等须说明适用性；不适用或无外部读者时可依据真实理由验收，不能据此跳过实际子 agent 评审。

仅详细维护当前和下一阶段，历史保留简要结论、证据和变更。实行双端门槛：主 agent 派前运行 `taskctl.py gate --book BOOK --stage ID --before KIND`；执行子 agent 在写任何实质产物前，自己读当前任务入口、核对本轮范围并运行相应 gate，不能只信派工消息中较早的通过结论。未通过时仅返回实际状态与缺项，不先写设定、构思、大纲、正文、评审等产物再补账。首读按 §2 的隔离例外操作。开书方向与新旧阶段门槛的结构及适用范围以[任务管理](task-management.md)为准，不另造 schema。`taskctl.py check --book BOOK` 或加 `--stage ID` 用于只读检查账本，存在合法 `todo` 不等于检查失败。写命令和账本修复仍交资料子 agent 执行。

每个实质任务单独走完“前置已验收 → 开始登记 → 产物回报并提交 → 主 agent 核验 → 验收记录”，才能执行依赖它的下一任务。开始前由资料执行者登记本任务实际状态和输入，不将一个派工包中的后续任务提前标为进行中。执行子 agent 产出后立即回报实际路径、输入与产物哈希、未完项；在继续任何依赖工作前，资料执行者用现有 `taskctl.py submit` 或 `update` 接口登记 `submitted`，不能攒到一章写完再统一补账。中断、失败或部分产出如实登记，不先写“完成”。接口与字段以[任务管理](task-management.md)为准。

`submitted` 只表示已提交，不是前置完成。主 agent 检查实际产物、输入版本、哈希、独立评审及授权后，再派资料子 agent 更新为 `done`，`verification` 留下真实验收依据。主 agent 的验收指令可在同一资料任务内登记，不把执行者的一句“完成”当作验收。输入或产物变化使证据过期时，按影响重新打开任务、保留旧记录并复核，不能只换哈希恢复勾选。

发现草稿、大纲等已经存在而前置任务未验收，或实质产物未登记时，立即停止后续创作与评审，先恢复真实账目。已有文件原样保留，不据存在自动勾完，不删除来消除异常，也不补造作者授权、先前开工记录或独立评审。只读核对作者原话、来源、版本和历史操作；由资料子 agent 登记真实产物和未完项，安排实际缺失工作或请作者作尚未作出的决定，经主 agent 核验后才恢复依赖执行。修复账目不等于认可越序创作，不能靠把草稿挂为任意输入洗成合法前置。

阶段结束由资料子 agent 运行 `taskctl.py close --book BOOK --stage ID`：该阶段必做任务全部验收，且已登记并细化 `next_stage`，或以 `end_reason` 记录本次授权结束。关闭只表示本阶段已验收并留好接续，不自动开始下一阶段或扩大授权。任务账本不替代作品状态、章节评审和 `pending_operations`；机械中断先沿原操作恢复，再核对任务状态。

## 2. 标准派工消息

创作、资料和评审的资料核查阶段使用以下模板；首读评审使用后面的隔离模板，不能直接转发此模板中的创作目标。向子 agent 提供具体任务，不能只说“去写得好一点”：

```text
身份：创作 / 资料 / 总编 / 评审-资料核查（当前稿写作与评审不得同一实际 agent）
稳定阶段/任务ID、任务kind与当前状态：与账本对应；本轮实际派工标识及agent标识由宿主补记
唯一作品书根绝对路径、Skill绝对路径、当前方案与输入版本：
用户目标与真实授权范围：附原话或已有决定记录
本次目标与验收条件：作者契约的适用范围、本章变化与详略/承诺取舍、待核实承重规则
读取范围：本书必读文件的精确路径、必要章节和资料；允许补充搜索仅限本书指定范围；列获准外部来源，禁止读取或检索其他由本 Skill 创作的书
上下文边界：不携带其他作品内容；主 agent 与接手者如有跨书污染，先停止并换干净上下文
写入范围：列可写文件或候选目录；列禁止改动部分
依赖与派工门槛：前置任务ID及验收状态、主 agent 的 gate 结果、执行者写前自行重跑的命令、输入文件的哈希/版本
产物：正文/资料/评审路径，关联出处、变化清单、未完项
返回：实际读取清单、修改、检查结果、证据、失败和下一步；产出立即回报并登记提交，未验收不得执行依赖任务
```

创作子 agent 不需要阅读全书秘密才能写一个有限视角；提供其所需写作边界，客观真相检查由连贯性评审掌握。

首读评审使用宿主支持的全新上下文，不继承创作对话、筹划历史或已有修改意见；同一实际 agent 曾读过这些资料时，不能仅换任务名就称为盲读。首读只传以下信息：

```text
身份：评审-首读；稳定阶段/任务ID、本轮实际派工标识：
唯一作品书根绝对路径、Skill绝对路径、必要阅读规则：书根只作路径边界，不读取作品索引、大纲、设定、任务账本或创作决定；不读取或检索其他由本 Skill 创作的书
中性任务与授权：阅读下列文本并保存反馈；列读取/写入范围，不附作者期待
中性状态与门槛：只给本任务当前状态、经过筛选的依赖检查结果、执行者自行运行的 gate --neutral 命令和阅读产物验收条件
正文输入：精确路径、阅读顺序与SHA-256；必要前文和题材背景同样列明
上下文隔离：不携带其他作品内容；是否不继承本书创作历史；已知接触或泄露限制
产物：自由反馈、实际输入清单及哈希、实际阅读范围、疑问与阅读限制
返回：产物路径及哈希；等待资料核查，不自行搜索创作资料
```

不透露作者意图、未揭示秘密、方案设计理由、预期评价或希望采用的修改方向；必要题材背景也不能夹带这些信息。不得把任务账本、权威 JSON 或含创作信息的依赖说明交给首读者。主 agent 先核查门槛，仅转交中性结果和精确 gate 命令；首读者不打开完整账本或作品索引，写反馈前自行运行 `taskctl.py gate --book BOOK --stage ID --before first_read --neutral`，失败只返回中性状态，不暴露内部证据文件名或原始异常。详细缺项由主 agent 另用普通 gate 或 check 查询，首读者不自行改用详细模式。未通过则返回状态，不先写反馈。若其他输入意外暴露创作信息，记录泄露范围并按实际独立性标注。必要前文须足以理解本章承接、人物关系与已作出的承诺，不能为隔离而让读者失去正常阅读条件；缺前文只限制相应判断，不能据此断言书中没有交代。首读先记录被打动、困惑、想跳读的位置、人物诉求理解及继续阅读的动力，资料子 agent 保存原件、输入清单与哈希后再补意图和有关资料；后续解读另存，不回写原件。若限制仅是评审已接触本书创作历史或额外读到本书意图，记录为普通评审及其限制，不伪称盲读，也不因此阻止已授权创作；任何跨书内容污染仍按 §1 停止并更换干净上下文，不能套用此降级。可移植记录依靠输入、产物和实际宿主信息，不依赖某个平台特定开关。

## 3. 新书流程

**作者决定边界贯穿开书、写章和返工。** 所有决定性创作选择都由作者选定，非穷尽范围包括：书名及恢复弃用名；视角、结构与风格；世界承重规则；人物命运、成长、关系；冲突如何解决及付出什么代价；转折、秘密、伏笔回收与结局。agent 主动给少量候选、推荐理由和代价，但推荐不是决定。未选候选只保留为明确标注的选项，不写入执行大纲、人物/世界有效设定或正文变相定案，也不借“只是草稿/试写”替作者选。

**免逐项询问只有一种来源。** agent 确实提出过选择“全部按推荐选项走且不用询问”的问题，作者明确选了这种方式，且实际问题、答复和适用范围均可核对，才可在该范围内按推荐执行。“你定”“帮我写”“AI 主导”“先试写”等泛泛委托不是这项豁免；部分回答或“全选 A”只解决其对应的已列选项，不等于未来所有推荐均免问。问题针对本批推荐时，免问也仅对本批有效；范围外新的决定性选择仍须询问。撤销、新反馈和缩小范围优先，不用旧记录压过作者改口。具体记录沿用[故事资料](story-records.md)的作者决定，结构由[任务管理](task-management.md)规定，不另造字段。

**弃用名不能靠泛授权恢复。** 检查本书当前名、曾用名及弃用决定；已弃用的书名不得当默认名、工作名或恢复现场时复用。若推荐重新启用，实际待选推荐须明确点名该名称并提示它曾被弃用；作者可单独选它，也可对这批清楚展示的推荐明确选择全部按推荐且不用询问。未指向该名称的泛授权或旧免问记录不能暗中恢复。作者主动明确指定恢复该具体名称时，不重复询问，记录其新选择并提示曾弃用的历史。书名未定时可保持未定或使用不冒充书名的中性工作标识，不能拿弃用名填空。历史文件中真实旧名保留为历史，不等于重新启用。

已定的具体选择不重复问；资料整理、机械执行、规范标点与错别字、且不改变含义和已定选择的局部修错可直接做，不因细微词句逐字请示。若修改改变人物决定、事件解法、世界条件或其他决定性取舍，就先让作者选；主 agent 负责合并同批问题，避免把每句写作变成审批。

1. 先只读理解作者已给构想和材料，识别已定选择与仍缺的关键方向。若缺少本轮所需的阅读/叙述偏好、资料推进方式或其他决定性选择，且无覆盖该项的有效免问记录，首次回复用一两句复述已知，仅补问一至三组关键缺项、给少量可比较选项及推荐，然后等待真实答复。有限探索仅含上述只读理解与回复中的选项，不派工补设定、构思、大纲、试写或批量建档。问过不等于答过，部分答复只解决对应问题；尚未回答的开工关键项继续等待，不将沉默、暂定字段或 agent 建议视为作者选择。可建议短试写帮助选风格，但先由作者选择试写范围及需比较的决定性变量，或核验有效免问记录覆盖它们。
2. 不要求一次确定未来全部选择：先了解本轮需要的目标读者/阅读体验、节奏与详略等方向，后续按需核对章长、对白与描写、钩子及尺度。已有具体选择不重复问；提供世界观只说明已有素材，不自动表示选择“先建资料”，也不必重问已给设定。作者明确要求整理资料或只试写时，可执行其确切任务；任务指令不豁免其中未定的决定性选择。单纯整理不强制完成整套访谈，但不能扩为补设定或写正文；只试写不能扩为全书推进。作者后续反馈可修订旧约定，来源、状态、范围与取代关系见[故事资料](story-records.md)的作者契约。
3. 收到本轮所需具体选择，或核验有效免问记录覆盖未定项后，按所选资料模式与本轮范围派资料子 agent 使用 `novelctl.py init` 建书、保存真实约定并细化自动创建的 `planning` 任务；已有目录先检查，不覆盖。再通过双端 gate，派创作子 agent 基于已定选择准备构思说明、设定或试写计划；仍缺的新决定性选择先作为选项交作者，不写成执行计划。需正式存档由资料子 agent 整理。作者不必提前决定所有未来设定；资料模式与合作方式分开记录，不能把同意先试写当成同意无限扩写。
4. 主 agent 验证目标、独创性风险和长篇支撑检验是否有产物，核验其选择依据；向作者解释方案，将新的决定性取舍交作者选择，仅已选范围的执行继续。
5. 开书及重大风格调整进入已选定的试写范围时，创作子 agent 对同一场景写两种实质不同的方案；先列出拟比较的视角、叙述距离、信息、时间压缩或描写密度，由作者选定比较范围或核验有效免问记录，不以同义改写充数。交未参与写作的评审子 agent 匿名首读，再结合资料核查比较得失；不透露推荐理由。最终方案由作者选择，或按覆盖该项的有效免问记录执行；资料子 agent 保存代表片段、实际选择依据、适用章/阶段与后续验证问题。短句、稠密等标签不能自行推出全程慢写、一段一行、不解释或禁止内心等硬约定；这些可作为提案，不得据此抹去首读反馈。第一章选择不自动推广全书；未定项保持未定，不把沉默当选择。
6. 采用的试写按逐章流程完成评审、授权与同步；未采用方案留在候选区。未知项保留未知，不拿猜测填充正式人物卡。

合作方式：作者逐章把关、关键节点把关、AI 主导调度执行、先试写；它们不取代决定性选择的作者选定规则。“AI 主导”本身不产生推荐免问豁免，也不豁免子 agent 评审。未选择合作方式时可执行已明确要求、且不需新增决定性选择的独立任务；否则等待，不默认试写，不借“有限探索”跳过停点。作者逐章把关须等待对具体版本的真实认可，试写后未选方式不能无限自动扩写。

资料建设模式另选：**先建资料**，先完成作者选定的关键世界、人物与结构约束，避免无关百科；**边写边补**，只建立足以试写的方向与当前承重规则，新增决定性设定先提选项、待作者选后生效；**混合**，先选核心规则与关键转折，其余随写提出并选择。未选且无覆盖该项的有效免问记录时只提出选项并等待，不能凭“你定”选择混合模式、先写小样或先补设定。三种模式都必须处理将决定眼前选择、代价或结局成立与否的关键缺口，不必先锁定所有未来细节。

已有素材的改编先明确保留、可改及待确认的事件、关系和结局，记录原件与衍生解读的地位。原件不随作品迁移时列外部依赖与可获得状态；哈希只能验版本，不能代替缺失内容。无法读到素材时说明忠实度核对的限制，不把对解读稿的解释写成原作者事实。

## 4. 每章流程与验收

可用四组顺序派工承接：① 资料准备验收后创作草稿；② 独立首读封存后资料核查；③ 写作者处理意见后另一 agent 复核；④ 资料采用、同步与后续计划。组内仍按依赖逐项提交和验收，一组可以包含多次实际派工；有返工则重复第③组。不能用合并派工跳过主 agent 验收，也不能把首读与秘密资料一次交付。对不可续聊的宿主，首读完成后新派核查任务并保存上下文来源，复核者如实记录是否看过原意见。

### A. 准备

资料子 agent 先组装当前故事时点的写作准备，列适用的作者契约、阶段目标、语言样本、视角、人物目标/成长/关系、知情、资源、地点规则、故事线与未兑现承诺，回看必要原文。总编对照近期正文简查本章是否重复、成长节点是否已发生、主承诺能否推进，并给写作边界；结论附现有准备或评审记录，不另开十套表。

关键生活、职业、历史或社会素材不足以支撑本章选择时，优先查清会封死退路、决定惩罚或支撑关键转折的承重设定，再查一般细节。主 agent 定向派资料任务，创作子 agent 检验其怎样改变行动与代价；来源只支持到哪一命题就记录到哪里，推论、未知和小说设定分开。需要新增或改变承重规则、虚构解法或情节条件时，先给候选、推荐和代价让作者选，或核验有效免问记录；泛泛允许虚构不能代替选定具体规则。不包装成史实，素材判断与转化方法见[文学指南](literary-craft.md)。

创作子 agent 基于作者已定选择或有效免问范围拟定场景，说明人物此刻诉求与可选行动、本章前后变化、详写/略写/跳过的取舍、时间空间及章间承接、读者主要期待和推进/兑现方式。若需新增人物走向、冲突解法、代价、秘密或其他决定性选择，先提交明确标注的选项，不把推荐写进执行场景或正文。按作者偏好给篇幅预算，不设统一章长、描写比例或反转次数。主 agent 核对选择依据、范围和完整性，不自行写故事方案作为子 agent 产物。

### B. 写作

创作子 agent 写草稿和候选变化，登记实际身份。草稿路径在 `草稿与备选/`，不直接更新正式正文或事实；不为补字数延长无变化过程，不用身体反应和意象替代人物诉求。未来秘密不得无途径进入角色知情。按作品标点约定检查对白、引语层级与符号；只读机械检查可定位候选问题，不能一键替换所有引号或替代语境判断。命令与可配置篇幅政策见[文件协议](file-protocol.md)。

### C. 独立评审

派另一实际子 agent，按第2节先首读、冻结反馈和输入证据，再提供资料核查。至少覆盖以下两类检查；可一人分阶段完成，也可拆为不同评审任务：

- 文学：人物诉求与有限条件下的行动、关系与成长、场景作用、详略和重复、情感积累、承诺与兑现、叙述与语言。总编结合近期正文核对跨章效果，不只看章内是否优美。
- 连贯性：时间、因果、空间与动作路径、代词指代、人物身体与资源、知情、关系、世界规则、线索与既有正文；确认新稿没有提前消耗未来计划的变化。

评审必须读实际稿，写明 SHA-256 和阅读范围。问题包含证据、影响、性质、严重度、建议与代价，按[文学指南](literary-craft.md)区分硬冲突、主要阅读问题、可选审美。硬冲突须解决；主要问题须处理或在授权范围内有理由保留并列复查点，不能因标为 soft 而无人处理；可选审美不阻断。主 agent 验证真实身份与产物，主动解释最重要的问题和有限方案，不能用自身文学判断代替缺失评审或用“有意设计”抹去首读反应。

### D. 返工

主 agent 按结构与人物、因果、场景节奏、语言的影响排序，把重要问题交写作者，不自己改正文。每项记录采用、部分采用或保留及代价；不改变已定选择的机械修错直接推进，任何新的决定性创作取舍均先给少量方案、推荐及代价让作者选，或核验覆盖它的有效免问记录，不能只在“核心方向越界”时才问。细微措辞不逐字请示。写作者提交新稿后，另一实际 agent 须对实际采用版本复核；影响清晰时可依据已读基稿、变化映射与关联范围增量阅读，证据链见[文件协议](file-protocol.md)。主 agent 看 diff、换报告哈希或承诺稍后补读均不替代独立复核。

派资料子 agent 按受影响范围重新打开账本中的任务和依赖验收，保留旧证据、返工原因及复核结果。前稿首读原件继续作为历史；已知意图的修订复核不是一次新读者盲读，不为恢复旧勾选伪造首读。确认无需正文修订时也留下依据，再验收修订与复核步骤。

两轮针对性返工仍受阻时，保留稿件、未解影响与可选方案，向作者说明代价，不无限加审。已按授权有理由保留的审美分歧，输入与影响未变时不因换评审反复重开；事实硬冲突仍须解决。未完成不能宣布完成。

### E. 正式采用与资料同步

1. 主 agent 先对 `adopt` 运行任务门槛；资料子 agent 检查采用授权及对应版本评审，保存完整快照。
2. 按文件协议执行 `chapterctl.py adopt`，取得正式正文哈希及 `operation_id`。采用任务先提交，主 agent 核验实际写入与操作记录后，派资料子 agent 以这些证据验收 `adopt`，不能在采用写入前勾成完成。
3. 正文采用后仍标记“资料同步中”；对 `sync` 检查前置任务后，资料子 agent 从候选变化回查正式正文，更新实际变化与相关引用，不把提案写成事实。
4. 更新章摘要、阶段进度、索引、历史、交接；筛查所有资料类别，撤销被新稿取代的旧指令，反查未来大纲、成长节点和承诺。逐条确认出处支持完整命题，推测不升级为事实；准确说明已查、无变化与待核实范围。任务账本、交接和正式/草稿状态须与实际产物及当前复核版本一致。
5. 资料完整后执行 `chapterctl.py finish` 关闭机械操作；此时 `sync` 可以为 `doing`，不得预先勾为 `done`。`finish` 成功后主 agent 核验产物，再派资料子 agent 验收 `sync`；发现缺项则修复。`finish` 仅表示本次采用后的资料同步完成，不表示阶段或全书文学定稿。

完整章节必须具有：正式正文、该版本独立评审、采用授权依据、变化筛查记录、同步资料、历史和可接续入口。

## 5. 阶段与整书

总编每章简查计划与成稿差异；试写后、阶段目标完成、重大转折或大改，以及连续拖沓/乏味反馈、承诺长期停滞、重复节点或风格漂移时，触发一组相关章节的完整连读。范围随风险确定并记录输入版本；不规定每三章必加一次审批，也不每章通读全书。检查跨章因果、主支线、成长与关系、读者期待/钩子与兑现、希望/挫败及松紧变化。需要写新稿仍派创作子 agent；总编短结论沿用阶段大纲、曲线或评审记录，只维护影响决定的内容。

“章节可采用”允许在写作中继续检验；“阶段定稿”或“全书定稿”还须对相应范围的完整版本做整体阅读，不能拼接逐章通过结论。评审子 agent 按首读与资料核查流程留存完整阅读范围和版本清单，说明作品实际取得的效果、主要不足与原文依据；创作子 agent 处理修订，资料子 agent 记录采用、拒绝或有意保留的理由，评审子 agent 对最终版本及关联影响复核。无须为凑流程强改正文；认为无需实质修订时也要留下理由与复核证据。审美分歧可以保留，未解决硬冲突不得宣称定稿。

全书拟定稿时，先按 `finalization` 任务验收整体阅读、结构修订处理与复核，由资料子 agent 据真实证据编写定稿记录；字段及证据规则见[文件与工具约定](file-protocol.md)。主 agent 对 `finalize` 运行 `taskctl gate`，只检查该任务的前置验收，不要求 `finalize` 自己先完成，再用只读工具取得清单并核验记录：

```bash
# 以下为 Bash 路径变量；python 须为 3.9+，Windows 可用 py -3 和实际路径
python "$SKILL/scripts/bookctl.py" manifest --book "$BOOK"
python "$SKILL/scripts/bookctl.py" check --book "$BOOK"
python "$SKILL/scripts/bookctl.py" check --book "$BOOK" --record 审稿与修订/全书定稿记录.json
```

`manifest` 给出当前按章号排序的 `number`、`path`、`sha256`，必须与整体阅读和最终复核对应。正文增删、顺序、路径、哈希或关联报告变化均使旧记录过期；派评审重新核对变化与整体影响、补足必要阅读后，由资料子 agent 保存新记录，再检查。工具只核验版本、证据和完成状态，不自动评文学分或认证获奖水平。没有有效定稿记录时，仍可按既有授权继续创作、导出工作稿；不能把工作稿称为全书定稿。

`bookctl check` 通过且主 agent 核验作者参与约定及实际整体证据后，才派资料子 agent 验收 `finalize`。随后落实下一阶段任务或本次授权结束原因，再用 `taskctl close` 关闭阶段；不能为了通过定稿检查而预先勾完定稿任务。

外部读者反馈需用户提供或明确授权联系；不能擅自发书稿。真实读者与子 agent 阅读分开标记。记录反馈版本、范围和独立性限制；主 agent 解释分歧并调度资料子 agent 留存。

缺外部读者时可以完成内部评审并定稿，但须注明尚未获得外部阅读验证；不能据内部通过宣称具有获奖保证。

## 6. 改稿、分支与接手

改早期设定：资料子 agent 出影响清单及出处，评审子 agent 检查风险，创作子 agent 改正文，重新评审受影响章，资料子 agent 同步。重要改动前快照。已采用章重写不跳过逐章门槛。

备选方案单独目录与方案标识，记录分叉版本。非当前方案不得改当前事实；选中后按修订与同步流程整合，不把两个世界结局混在一起。

接手先读交接、状态、任务账本、意图及语言样本；检查文件哈希、当前任务的依赖验收与未完成操作。旧宿主任务仅作历史证据，新环境沿稳定任务ID重新派工。新旧阶段或门槛版本混用时，按[任务管理](task-management.md)恢复各阶段真实适用范围与未完项，不为获得新版本通过而重写旧稿、伪造已执行步骤或追认作者答复。资料子 agent 修复过期资料或迁入缺失账本，评审子 agent 补缺评审。用户的手工正文先保留，不能直接用旧快照覆盖。

## 7. 调度验收清单

- 实际子 agent、任务和角色有记录？同一实际写作者有没有冒名自评？
- 本轮是否只绑定一个作品书根；读取清单是否在本书与获准外部来源内？是否跨书读取、转述或携带另一作品上下文，发现污染后是否换了干净上下文？
- 派工是否对应稳定阶段/任务ID，主 agent 派前与执行者写前是否各自运行 gate 并通过？执行者提交与主 agent 验收是否分开？
- 每项实质产物是否立即回报并登记提交，依赖执行前是否已真实验收？已有草稿与前置未完成的异常是否先恢复真实状态，而非攒到章末补勾或把存在当作通过？
- 输入版本是否一致，评审覆盖的是否正是采用稿？原文证据能找到？
- 首读是否真正隔离且未读任务账本，输入清单与自由反馈是否在补充创作资料前冻结？不能隔离时是否标明普通评审限制？
- 决定性选择是否有作者选定或有效免问记录；免问是否有真实问题、明确答复和当前范围，部分回答/全选 A/泛授权是否被越界扩大？弃用名是否未经点名恢复？
- 文件真的写成，待完成操作已关闭，手改与并发没有被覆盖？
- 正式事实、摘要、索引与交接是否对应新稿？“无变化”是否有筛查依据？
- 作者偏好和授权是否有来源、状态、适用范围与取代关系；开书资料模式是否与合作方式分开？缺关键答复时是否先问后等，部分答复和风格标签是否被越界扩用？
- 总编简查及触发连读是否有实际依据；主要阅读问题是否已处理或按授权保留；可选审美是否被误当硬门槛？
- 实际采用稿是否由独立 agent 完成全文或有基稿链的增量复核；是否撤销过期指令并反查未来计划？
- 是否保留创作风险、文学分歧和未核实项，而非宣布所有问题都解决？
- 声称阶段或全书定稿时，是否有完整版本的整体阅读、修订处理和复核证据；全书定稿检查是否对应当前正文及报告？
- 阶段关闭是否全部必做任务已验收，并留下已细化下一阶段或本次授权结束原因？是否仍遵守原授权边界？

主 agent 只在这些验收条件成立时报告完成；否则派工修复或报告阻塞。
