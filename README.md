# 长篇小说创作 Skill · ai-novel-editor-skills

一个面向长篇小说创作的 **Agent Skill**：主 agent 负责沟通、规划、派工、行政账本写入与验收，**正文写作、资料收集维护和逐章评审全部交给真实子 agent**；作品记忆以普通文件保存，换会话、换工具后可以接着写。

> A skill for writing book-length fiction with real sub-agents. The orchestrating agent never writes prose: drafting, worldbuilding records and per-chapter review are delegated to separate sub-agents, and all story memory lives in plain files, so you can resume the novel in any other agent tool.

- 实现入口：[`novel-studio/SKILL.md`](novel-studio/SKILL.md)
- 使用说明：[`使用说明.md`](使用说明.md)
- 验证记录：[`验证记录.md`](验证记录.md)

---

## 一、它解决什么问题

让 AI 写几千字不难，写一本八十章的长篇很难，难点不在文笔而在三件事：

| 难点 | 本 Skill 的做法 |
| --- | --- |
| **记忆漂移**：人物伤势、物品、秘密、伏笔过几章就自相矛盾 | 每部作品是一棵普通文件夹，重要事实带稳定对象 ID、故事时点、章节原文出处与核对哈希；摘要只做定位，不替代原文 |
| **自己评自己**：同一个上下文写出来的稿子看不出问题 | 逐章交给**未参与写作**的另一真实子 agent 独立评审，先隔离上下文首读、保存原始反馈，再核对作者意图与设定 |
| **跨会话断裂**：换会话/换工具就接不上 | 索引、交接说明、状态 JSON、任务账本都是文件；新工具加载同一 Skill 即可续写，不依赖旧会话还活着 |

先确认作者希望的题材、目标读者与阅读体验，支持文学表达、类型叙事、情节追读或混合目标；不以单一审美处理所有作品，**不用自评分代替阅读证据**。

## 二、核心约束：主 agent 不写正文

这是本 Skill 与"让 AI 直接写小说"最大的区别，也是它不肯降级的地方。

- **主 agent**：统一与作者沟通、制定阶段计划、调度子 agent、跟踪、验收成果和组织返工；可抽验原文与来源，不自行承担一轮资料检索收集。
- **创作子 agent**：构思、试写、正文、改写。
- **资料／调研子 agent**：本地资料检索筛选、外部搜索与原文阅读、摘录整理归档；人物/世界/摘要/索引/历史/交接；任务账本由主 agent 登记。返回来源、已读范围、支持边界、冲突和未解项，由主 agent 验证后采用；需要用户补充的信息由主 agent 统一询问。专项内容分别交给其 owner。
- **钩子管理子 agent**：维护钩子管理文件，主动安排承诺推进、兑现和承接，追踪遗失或拖延的钩子。
- **故事线管理子 agent**：维护故事线管理文件，管理主支线、成长及关系线的因果、推进、交汇与收束。
- **起伏曲线管理子 agent**：维护故事起伏曲线文件，主动主导写前加压、松弛、积累、兑现、余波与详略方案，结合实际阅读反馈提出节奏修订。完整模式三者分别由真实专职 agent 承担；轻量模式可用真实规划子 agent 的联合包，决定性选择仍遵守作者约定。
- **暗线管理子 agent（可选）**：先由主 agent 询问作者是否需要暗线，选择需要后才安排专职真实子 agent，维护幕后因果、明暗线交汇、线索、知情与揭示的计划和实际；拒绝不建档、不派专项。
- **评审子 agent**：当前稿的文学与连贯性评审，且必须与写作者不同。关键行动者另由真实子 agent 分别代入，使用角色卡及当时可知信息核查行为、对白与行事风格；角色视角报告交全稿编辑核验，定稿时也纳入关键行为复查。角色任务禁止用“不适用”跳过；派工材料的路径、标题和 ID 也须筛查，内部定位可经中性 `gate --book-ref` 隐藏。
- **全局总编子 agent**：独立于当前稿写作者，持续检查主线、人物变化、详略、章际重复与承诺兑现；按触发条件连读一组章节，不替代隔离首读。

不能靠换一个角色名、在主 agent 回复里模拟对话、或"顺手修复"绕过分工。宿主如果提供不了真实子 agent，会明确说明执行条件不足并保留现场与迁移指引，**不会退化成主 agent 代写代评**。

## 四、默认执行闭环

```
进入现场 → 理解与规划 → 派准备任务 → 派创作任务
   → 派独立评审 → 采用与同步资料 → 验收与汇报
```

1. **进入现场**：读顶层 `索引.md`、`创作约定/写作进度与接续说明.md`、`作品状态.json`、`任务计划与验收.md`；检查未完成操作、任务依赖、手工修改、正文版本与评审状态。
2. **理解与规划**：恢复作者目标、章长、详略、语言、阅读期待、是否需要暗线及已定选择，区分先建设定、边写边补、混合三种开书方式。缺决定性选择且无覆盖该项的有效免问记录时，先补问并等待，不边问边派设定、大纲或试写任务；已定具体答案不重复问。需要且已选定比较范围时做**同场景两种叙述方案对照试写**，记录选择范围，不把单章声音自动推广全书。
3. **派准备任务**：资料／调研子 agent 检索收集并按时点组装依据；总编给本章全局约束，创作子 agent 明确人物诉求、本章变化和详写／概述／跳过的安排。
4. **派创作任务**：创作子 agent 写入草稿区，提交正文、依据与候选变化，**不改正式事实**。
5. **派独立评审**：另一位真实子 agent 首读隔离、保存原始反馈后再核对意图；记录输入版本、阅读范围与证据。
6. **采用与同步**：满足授权、无未解决硬冲突、主要阅读问题已处理或按授权有理由保留，且当前稿独立复核及适用的机械检查通过后，资料子 agent 保存快照 → 登记待完成操作 → 纳入正式版本 → 按变化更新所有受影响资料与索引。主 agent 直接维护行政账本和验收状态。
7. **验收与汇报**：核对实际产物、版本、主要问题处理与未完项，合格才算 `done`。主动向作者说明重要阅读问题、建议及取舍，不以档案数量或检查通过代替作品效果。

每次写章都走完整闭环。草稿可以保存、讨论，但**缺独立评审或资料未同步的章节不算完成**。

仅交试写候选和独立反馈用 `trial_only`，方向确认后可单独结项，不要求选声或采用。只整理已有资料用 `materials`，只读审稿用 `review_only`：本轮范围核验后直接整理／审稿，再以真实终点关闭阶段，不强制进入构思、写章或采用。初始化支持 `--workflow`，已有初始空骨架可按任务管理显式改派并保留历史。

任务状态须随每个产物即时维护：前置未验收不开始后续，产物返回先提交登记，主 agent 核验后才记 `done` 并派下一步。发现“第一章草稿已有、方向或准备仍未完成”时先停创作，保留原稿、核实真实来源和缺项，不能按文件存在自动补勾。

**写一本书，只读取这一本书的作品内容。** 作者指定当前书根后，搜索和派工只限本书；其他由本 Skill 创作的书的正文、设定、大纲、摘要、评审、快照、压缩包和旧 agent 记忆都不能读取或用作样本。不扫描整个作品库，也不把其他书复制进当前目录绕过隔离；全部推荐免问授权不放宽这条边界。若上下文已混入其他书，换隔离上下文再创作。

新 v2 阶段另以 `result_gate_version: 1` 核对采用操作、固定同步完成凭据和有效定稿记录，普通报告不能代替实际操作。未登记资料检测覆盖人物、世界、摘要等作品目录；持续维护的主文件通过不可变任务依据关联本轮版本。采用备份及完成凭据也纳入完整性检查。

新阶段默认使用 `workflow_version: 2`：在现有任务中绑定作者约定、总编、章节设计、阅读体验及资料同步的验收证据；最终稿使用版本明确的 v2 评审和可重算的正文检查报告。小改可由独立评审增量复核，主 agent 看 diff 不能代替。旧阶段缺版本视为 v1，保留历史且不补造过去的验收。

新建 v2 阶段还执行作者决策门槛：书名（含弃用名复用）、人物走向、关系、冲突解决、世界规则与结局等决定性内容先给作者选择，再执行。只有实际询问后，作者明确选“全部按推荐且不用询问”，才在该范围免逐项再问；泛泛“你定”、部分回答或连续采用授权不等于此模式。已选具体事项不重复问。主 agent 派工前与执行子 agent 动笔前都要核验任务门槛。新建 v2 规划阶段另有 `hidden_plot_gate_version: 1`，要求方向任务记录暗线 `enabled/disabled` 的真实决定；初始化可选 `--hidden-plot-decision`，仅 `enabled` 额外建暗线空入口，省略不代表拒绝。旧已验收方向不追溯改写，后续确定方向时核对新选择。字段见[任务管理](novel-studio/references/task-management.md)，初始化对象见[文件协议](novel-studio/references/file-protocol.md)。

全书章目使用内置 `outline` 流程：候选 → 独立审读 → 至多两轮针对性修订／复核 → 当前版本最终验收 → 接续。只把行动不可执行、关键时间／身份互斥、结局因果断链或违背作者硬边界列为结构阻断；史实待核与局部留白按影响追踪。报告完成、修订完成、章目通过分别记录，最后通过还须作者明确确认当前候选。到达两轮上限仍有阻断时给作者具体选项及代价，不无限加审；作者明确选定最终报告中的结构方案后，可用 `outline-rescope` 保留旧阶段未通过状态、开启新范围的章目阶段，仍须审读及最终确认。最新审读已通过但作者明确要求修改时，同一命令的 `choice.mode: author_revision` 可绑定新反馈及当前候选／报告，保留旧阶段并开启新章目范围，不要求先确认旧稿；新稿仍须重新审读及作者确认。详见[任务管理](novel-studio/references/task-management.md)。

长篇默认完整专项规划，也可按范围采用一份轻量联合包覆盖故事线、钩子和起伏；独立章目审读、硬风险核对与版本复核不可省。项目明确的按卷／章／批次交付优先于默认逐章交稿，按卷交付不强制每章停等作者点头。已约定先确认全书章目时，章目通过并确认后直接启动第一卷准备及首章，不为非承重待核项新增全书级审批；未确认不得写正文。

## 五、安装

Skill 本体就是 `novel-studio/` 这个文件夹（含 `SKILL.md`、`references/`、`scripts/`、`agents/`），把它放进宿主支持的 Skill 目录即可。`agents/openai.yaml` 仅供 Codex 界面显示名称与默认提示，其他宿主直接读取 `SKILL.md`，不会因该文件自动获得交互入口或子 agent 能力。例如（Bash）：

```bash
git clone https://github.com/guofengli1214-cmd/ai-novel-editor-skills.git

# 示例：Claude Code 的技能目录
mkdir -p ~/.claude/skills
cp -r ai-novel-editor-skills/novel-studio ~/.claude/skills/

# 也可直接散放到工具约定的 skills 目录，或在支持路径读取的工具里指向 SKILL.md
```

要求：

- 宿主 **必须提供真实子 agent**（派生子任务、传递资料、取回结果）和普通文件读写能力；顺序派工即可，不要求并发。
- 脚本仅用 **Python 3.9+ 标准库**，不需要数据库、向量库、MCP 服务或任何第三方包。

命令示例使用 `python`，先用 `python --version` 确认是 Python 3.9+。Linux/macOS 若只有 `python3`，将命令中的 `python` 替换为 `python3`；Windows 可用 `py -3` 替换，不依赖 `python3` 的应用商店占位符。示例里的路径和变量也须按实际 shell 替换，不能把 Bash 的 `NAME=value` 直接粘贴到 PowerShell。

## 六、快速上手

开新书：

> 使用 $novel-studio，在 `/我的作品库` 新建《雾港来信》。先讨论方向，再试写第一章。由子 agent 写作和维护资料，每章交另一位子 agent 独立评审。

接手续写（不需要旧聊天记录）：

> 使用 $novel-studio，接着写 `/我的作品库/雾港来信`。先检查交接和未完成更新。

其他常用请求：

- "查一下主角到现在知道了哪些秘密。"（走资料索引，不重新通读全稿）
- "第三章的伤势会不会和第八章打架？"（查连贯性记录 + 原文出处）
- "先查本书已保存的参考资料，缺失或失效的部分再补搜；把新查到的有效结论、出处和待核实项保存下来。"
- "把主角妹妹改成姐姐，列出所有要跟着改的地方。"
- "从编辑角度看看这五章为什么不好看。"
- "导出当前工作稿到 `/导出/雾港来信.md`。"

### 四组顺序派工示例

完整模式普通一章可按下列四组组织；轻量模式的专项依据与更新可由联合包承接，不要求每个账本子任务都新开一个 agent：

1. **准备与草稿**：启用暗线时先验收暗线方案，三位基础专项 agent 分别提交与之衔接的故事线、钩子和曲线方案，曲线方案主导起伏；资料子 agent 组装依据，主 agent 验收 `prepare` 后，创作子 agent 提交草稿与候选变化。
2. **首读与核查**：另一真实评审 agent 先隔离首读并封存原始反馈，主 agent 验收后，按角色隔离派工，代入关键行动者核查行为与行事风格，再由全稿编辑结合意图和资料完成核查；宿主不支持结束后续聊时，新派真实 agent 并保留前一份反馈和输入哈希。
3. **意见处理与复核**：创作子 agent 处理意见；主 agent 验收修订，再由未参与写作的评审 agent 复核当前稿。无需改正文也记录理由，确需返工时重复这一组。
4. **采用与同步**：资料子 agent 采用；完整模式三位基础专项及已启用的暗线 agent 各自更新正式实际并交不可变依据，资料子 agent 汇总其他资料和索引、关闭待办；主 agent 在关键节点验收，再记录任务完成与下一阶段。

这是产物分组，通常包含多次实际派工；不是把四组当成四次工具调用，也不能跳过任务依赖、主 agent 验收、独立评审或修订后复核。

## 七、作品目录结构

每部小说保存在独立作品目录（书名或中性工作标识），**正式章节在顶层**，资料进子文件夹，活动目录都有 `索引.md`；工具生成的快照和采用日志归档由历史父索引链接，不补写或改动其内部文件：

```text
书名/
  索引.md
  第0001章-有意义的标题.md        当前采用的正式正文，全书连续章号
  创作约定/                       意图、作者决定、语言标准、作品状态、交接与任务计划
  大纲/                           全书、阶段、章节与场景计划
  人物/                           基础人物档案
  世界与地点/                     地点、规则、组织、世界历史
  参考资料/                       按需保存外部调研、主题记录、索引与获准原始附件
  连贯性记录/                     故事时间、角色状态与知情
  线索与悬念/钩子管理.md          钩子专职 agent 的计划与实际
  故事线/故事线管理.md            故事线专职 agent 的计划与实际
  曲线与节奏/故事起伏曲线.md      曲线专职 agent 主导的起伏安排
  摘要/                           章、阶段、全书摘要
  审稿与修订/                     评审 JSON 及可读意见、修订与变化记录、全书定稿记录
  草稿与备选/                     未采用正文、候选资料、独立备选方案
  历史版本/                       快照及操作备份
```

授权初始化会建立三份基础专项管理文件与索引，尚无规划时明确待规划／未分析，不生成故事内容。主 agent 开书时另问是否需要暗线；已有明确答案不重复问，未答不擅自启用。选择需要才建立 `故事线/暗线剧情管理.md` 并派专职 owner，纳入写前、评审、采用后同步与定稿；纯 `materials/review_only` 不为此补创作问卷。既有书可登记沿用同义主文件。其他目录如 `参考资料/`、`关系与成长/`、`事件/`、`资源/` 按实际内容增加，**不预建其余空表**。复制整个作品文件夹即可迁移。

外部查证得到的有效资料由资料子 agent **当轮保存**至当前书的 `参考资料/`，不等章节采用，尚未用于正文的材料也保留；仅只读审稿时查证内容存入获准审稿记录。按主题记录可复用结论、必要摘录、来源与实际查阅日期、适用范围、关联设定／场景及待核实、冲突或过期状态；`索引.md` 提供关键词／别名、已查问题和结论位置、未解缺口，获准附件按需存入 `原始附件/`。后续先查本书本地资料，命中且仍适用就复用，仅对缺失、失效、冲突、范围不同或作者明确要求重查的内容补搜并记录原因。只存网址或留在聊天记录不算完成保存；外部事实也不自动成为小说设定。具体记录与任务验收见[故事资料](novel-studio/references/story-records.md)及[任务管理](novel-studio/references/task-management.md)。

## 八、脚本命令参考

`SKILL` = Skill 文件夹绝对路径，`BOOK` = 作品绝对路径。所有脚本输出 JSON（`novelctl check` 输出 `OK`/问题列表）。

| 命令 | 用途 |
| --- | --- |
| `novelctl.py init` | 先验证作者选名或明确暂缓定名记录；可用独立中性工作目录；可选 `--hidden-plot-decision` 按真实选择建立暗线入口，不覆盖已有作品 |
| `novelctl.py index` | 刷新索引自动链接块（保留手写说明） |
| `novelctl.py check` | 检查路径、索引、版本与哈希 |
| `novelctl.py snapshot / restore` | 整书快照；只从当前书自己的历史目录恢复 |
| `novelctl.py export` | 按章号合并导出正式章节到作品目录外 |
| `chapterctl.py adopt` | 按请求采用当前稿（校验评审、授权、版本） |
| `chapterctl.py resume` | 核对原操作档案、现场及当前门槛，继续中断的采用，不创建第二次采用 |
| `chapterctl.py finish` | 关闭该次采用的资料同步待办 |
| `chapterctl.py unlock` | 确认无写入者、核对 pending 后解除残留锁，不删除操作记录 |
| `chapterctl.py check` | 检查待同步操作与章节状态 |
| `chapterctl.py diff` | 只读生成基准稿到当前稿的精确差异与版本映射 |
| `bookctl.py manifest` | 输出完整章节清单（章号、路径、哈希） |
| `bookctl.py check` | 只读核验全书定稿记录与报告版本 |
| `taskctl.py init / plan / update` | 初始化、规划阶段、更新任务 |
| `taskctl.py defer` | 定稿发现改章需求时暂挂，逐章修订同步后返回重新全稿核查 |
| `taskctl.py submit` | 一次登记产物、版本和检查证据，提交待验收，不自动完成 |
| `taskctl.py gate` | 派工及写入前核验前置验收、目标输入版本与当前待办限制 |
| `taskctl.py close` | 关闭阶段（须有后续计划或真实终点） |
| `taskpeek.py` | 正式解析账本、回读任务状态及核验哈希／索引；回读失败先查实际状态，不重复提交 |
| `taskctl.py render / check` | 重新渲染勾选视图 / 只读检查账本 |
| `prosecheck.py check` | 只读统计正文并定位引号、标点和约定篇幅疑点；v2 采用时重算硬约束 |

```bash
SKILL=/绝对路径/ai-novel-editor-skills/novel-studio
BOOK=/绝对路径/作品库/雾港来信

python "$SKILL/scripts/novelctl.py" init --parent /绝对路径/作品库 --title 雾港来信 --title-decision /绝对路径/书名决定.json
python "$SKILL/scripts/novelctl.py" check --book "$BOOK"
python "$SKILL/scripts/chapterctl.py" check --book "$BOOK"
python "$SKILL/scripts/taskctl.py" check --book "$BOOK"
python "$SKILL/scripts/taskctl.py" gate --book "$BOOK" --stage S02 --before review
python "$SKILL/scripts/bookctl.py" manifest --book "$BOOK"
python "$SKILL/scripts/bookctl.py" check --book "$BOOK"
```

日常只读检查可对 `novelctl check`、`chapterctl check` 或 `bookctl manifest` 加 `--skip-snapshots`，跳过历史快照 payload 的完整校验以降低耗时；默认仍完整检查。快速模式不代表归档完好，恢复、`finish` 和全书定稿检查继续验证快照。

PowerShell 示例（把路径换成实际值；无需 Bash 变量语法）：

```powershell
py -3 "C:/skills/novel-studio/scripts/novelctl.py" init --parent "D:/作品库" --title 雾港来信 --title-decision "D:/请求/书名决定.json"
py -3 "C:/skills/novel-studio/scripts/novelctl.py" check --book "D:/作品库/雾港来信"
```

`taskctl` 的初始化、计划、状态、返工与验收写命令由主 agent 统一执行，纯验收不另派子 agent；`novelctl/chapterctl` 的作品资料、采用、同步等写命令仍交相应子 agent。主 agent 用 `taskpeek`、`check`、`manifest`、`gate`、`diff`、`prosecheck check` 回读和核验。请求体字段以脚本 `--help` 为准，不要猜。

## 十、已知边界

- 脚本只能验证**机械约束**（路径、哈希、版本、门槛、依赖），**无法认证**子 agent 的真实身份、作者确实批准，也无法判断文学质量——这些必须由主 agent 对照宿主任务记录与真实对话核验。
- `check` 通过 ≠ 小说好；自评分、档案数量、曲线形状都不代表文学水平。
- 拖沓、人物吸引力和钩子效果由独立阅读与总编判断。主要阅读问题须处理或按授权明确保留，纯审美建议不机械阻断；不设普遍适用的章长、对白比例或反转数量。
- 尚未完成百章级长篇的持续创作验证，也没有独立外部读者对完整长篇的评价，因此不宣称"保证获奖"。
- 辅助脚本不支持自动改章名、重排、软删除、DOCX 导出；这些按文件协议由资料子 agent 维护普通文件处理。
